# DSH 呈现选型

先排除文字和原生方式更合适的简单场景，其余可呈现的需求默认优先使用json-render，并选择足够表达内容的组件。同一任务可以按阶段切换；渲染失败时保留完整内容和草稿，降级为文字或原生方式。本技能适用于模型可选择、最终用户可见的输出，不用于产品内部控件设计。

## 决定当前呈现

用户明确指定方式时先遵从；确实缺少必需能力时说明折衷。依据用户需求、已有草稿和本阶段动作判断，不根据“预约”“地图”等关键词直接套组件。

先检查以下例外，命中时无需为渲染而额外调用render_ui：

- 简短事实、概念解释、少量建议、1—2步简单说明、小规模固定比较，以及只需复制的一小段代码、命令或链接，直接文字/Markdown即可。仅给一两句话或短清单加外框，没有增加内容组织或阅读便利时也保留文字。
- 单次接收/提交回执、简单状态通知、错误说明、控制回执，或一次明确的单字段改值，用文字及必要确认。
- 是否确认，或一次可完成的1—2项简单独立信息选择/补充，优先原生提问；同一任务的多字段填单按下文规则集中呈现。一张证据图、两图对照、逐次补拍及已有静态地图说明，优先原生图片配文字。
- 用户明确要求纯文字、Markdown、代码或其他固定输出格式时按要求交付，不额外生成界面。

不属于这些例外时，在事实足够且当前组件支持的前提下，默认调用render_ui。多项多属性对照、分组资料、较完整的报告/方案、可浏览的说明页和其他结构化答案，即使只读、不需要点击，也优先用json-render展示；无需等到用户明确要求交互才使用。工具不可用、缺少必要事实或所需动作不受支持时，先澄清或采用可交付的替代，不明知缺能力仍调用。具体约定见[默认渲染与降级](references/capabilities.md#默认渲染与降级)。

|当前需求|优先方式|
|---|---|
|短答、简短手续说明、一次回执、少量固定比较|文字/Markdown|
|不命中文字/原生例外的结构化答案、完整报告、分组资料、多项多属性比较|优先使用json-render的展示组件，支持只读呈现|
|分析真实数值的趋势、类别差异、排名或整体构成，图表有助于理解|优先使用json-render Chart，并配分析结论|
|展示3个及以上有明确先后关系的操作步骤，供用户逐步查看|优先使用json-render Steps步骤条|
|是否确认、一次收集1—2项简单独立信息|DSH原生提问，例如可用的 ask_user_question|
|一张证据图、两图对照、逐次补拍|DSH原生图片；需要确认时接原生问题|
|同一任务需填写或修改3项及以上相关业务字段，或需整单核对、字段联动、附件关联及提交|json-render DynamicForm，集中展示并统一提交|
|用户自主切换分类、按需展开详情|json-render Tabs/Collapsible|
|用户直接调序、试排并应用|json-render SortableSequence|
|用户直接编辑流程步骤、参数、条件分支并保存|json-render Workflow|
|静态位置/路线说明|原生地图图片+文字即可|
|地图探索、交互筛选、持续看板|先核实相应组件接口与数据，再采用匹配的动态呈现|

同一任务需要用户填写或修改3项及以上相关业务字段时，优先使用json-render动态表单，一次展示并统一提交；不因原生提问单次可容纳的问题数有限，就将同一份草稿拆成多轮填写。字段数按本轮需要集中填写或核对修改的不同业务信息计算，单字段的候选数量、只读说明和按钮不计入。已有值应预填；不重新询问已知信息，也不为达到阈值增加无关字段。用户明确希望逐步填写时遵从。

仅需确认、选择或补充1—2项简单独立信息时，优先原生提问并尽量一次收集。两项信息涉及字段联动、整单核对或反复修改时，也可使用动态表单。仅补一个缺项时，不因背景材料包含多个已知字段而强制打开整单。缺少真实菜单、候选或决定字段结构的关键信息时，先获取材料或一次澄清关键缺项；业务允许自由填写时使用输入字段，不编造候选。只要排好事项顺序的结果，用文字列表；只解释流程，不创建编辑器。

操作说明达到3步时，优先用Steps展示步骤及必要说明；1—2步通常用文字。三条并列建议、清单或比较项不因数量触发Steps；用户要求一句话、简短文字或纯文字时遵从。Steps展示顺序不代表执行，未有真实进度时不声称已完成或当前正在某一步。组件不可用时保留完整步骤并用文字降级。使用要求与示例见[能力说明](references/capabilities.md#步骤条的适用范围)和[步骤示例](references/examples.md#多步骤操作说明)。

涉及有真实数值依据的数据分析，且图表有助于表达趋势、差异或构成时，即使用户没有明确要求画图，也优先使用Chart。用户未指定图型时，模型根据分析目的、数据关系和当前支持能力自行选择，无需仅为选图型再次追问；当前优先用柱状图比较类别、折线图表达时序趋势、环形图表达同一整体的非负构成。用户明确指定图型或纯文字时先遵从；指定图型不受支持或不适配数据时说明并给合适替代，不虚构能力。定性分析、单个数字或简短计算不强制画图；多种单位及文字属性混合的比较仍可保留表格。数据结构与示例见[Chart选型与数据](references/capabilities.md#数据分析与chart选型)和[图表示例](references/examples.md#数据分析自动选择图表)。

## 随阶段切换

先识别本轮是否仍在咨询、看证据、填写、核对、确认、提交或读回执。阶段变化时重新选型，不延续整段会话的固定组件。

预约示例：简单手续咨询用文字，较完整的分组指南用展示组件 → 用户要求填单后用动态表单 → 尚未确认时原生一次确认或使用现有表单的明确提交按钮 → 根据真实回执给文字结果。已有按钮完成同次提交确认时，不再重复弹问题。

切换时保留已知字段、用户修改、对象及附件关联、当前提交状态；不重新询问已有值，不将业务对象换成显示顺序或标题。

## 展示属性的类型

生成Section、Steps或Table等展示前，参照[静态属性与绑定](references/capabilities.md#静态展示属性与绑定)及[正反例](references/examples.md#静态标题说明与表格类型)。当前Section的title/description、Steps每项title/description要求字符串字面量；Steps.items是数组，Table.columns是字符串数组，Table.rows是二维字符串数组。不要把整段业务对象、富文本对象或$state/$item/$bindState引用对象放入这些位置；并非所有组件属性都支持动态绑定。

将涉及这些组件的简短类型约束写入render_ui的user_query，让服务内生成模型也收到；完整事实仍放在business_data。只限制schema要求静态值的属性，不取消表单当前值绑定、事件回传或组件已声明支持的动态属性。可检查返回spec时核对类型；发生expected string, received object时按路径与事实修正生成要求，不只原样重试，不把对象强转成“[object Object]”或原始JSON应付校验。

## 通用表单输入

调用render_ui生成通用表单前，按[表单结构与自检](references/capabilities.md#通用表单结构与自检)组织事实，并参照[完整调用及反例](references/examples.md#通用表单输入与选项位置)。business_data是业务事实输入，组件schema约束的是最终UI spec；business_data.fields是便于生成的建议约定，不是所有业务JSON的必需结构。

DynamicForm中的select/multipleSelect字段把候选放在value.options，条目为{value,label}，已知默认选择放在value.default；不要把options放在字段外层，也不要只传标量默认值就假定有候选。独立Select使用props.options，不能套用DynamicForm字段格式。单选默认值用字符串，多选用数组；值须对应真实候选，用户未选择时不擅自预选。字段键、字段类型和其余参数以当前工具与组件说明为准。

调用前核对字段key、值类型、候选来源和默认值；可见结果可检查时还要核对候选是否可选。schema通过不保证下拉有数据。缺少真实候选时先澄清，或在业务允许时改自由输入；不编造选项，不将修正结构说成已验证页面可用。

## 表单按钮与动作

生成带提交、保存、确认、重置、跳过、放弃、继续新增或跳转入口的界面前，阅读 [按钮预设与回传](references/button-actions.md)。面向Agent的表单操作统一表达为“用户意图+点击时最新表单数据”回传，由Agent决定下一步；包括重置，不把它默认当成本地恢复。提交到Agent不等于提交真实业务。按钮文案不是动作协议，on.press只是绑定位置；仅绑定当前宿主已接通的事件和参数，不能自造confirm、reset、skip等事件名。

默认未指定额外操作时可以只有提交按钮。用户明确要求多个表单操作时，必须使用当前工具的form_actions声明完整列表，每项包含受支持intent与忠实于职责的label；DSH统一生成同级并列Button，小屏可换行。不能默认改成Select/Radio操作字段，也不能因为只接通form.submit就推断只能有一个按钮；这些按钮共用提交事件，各自携带意图并自动收集点击时的最新表单值。完整列表包含需要的submit；设置form_actions后不另用submit_button/submit_label控制动作栏。重置需可靠初始草稿，Agent收到reset和当前值后再恢复；跳过不假装完成业务，不为回传意图伪造缺项。

只有当前部署确实没有form_actions，或得到明确的不支持/校验失败证据且无法修正时，才说明限制并用原生选择或“操作选项字段+一个已接通提交按钮”保留全部意图。一次渲染失败不证明多按钮能力不可用；先按错误修正一次，仍失败才降级。操作选择须跟最新数据一起到达Agent，不能只按不同文案猜操作。

打开链接等导航按已支持的链接能力处理，无需冒充表单提交；纯本地字段编辑、展开或切换不自动触发Agent。保存、放弃或继续新增均按实际意图与业务回执处理，不因按钮点击就宣称保存、取消或提交成功。

界面有按钮不等于业务已执行。form_actions由宿主组装和绑定；没有声明列表的旧表单仅保证默认提交，不推定任意自定义事件已接通。调用前以当前工具schema为准，不向旧部署添加未声明参数。

## 落地与结果

读取当前可用工具的说明、schema和宿主事件；组件名称不证明筛选、实时位置、控制或持久化可用。特殊接入、地图、流程或失败情形参阅 [能力与交付边界](references/capabilities.md)。

证据先于确认实际可见。若display卡片要到最终回答才显示，不能先阻塞在原生问题上让用户确认未见图片；先完成证据展示，或采用已接通的同屏证据与确认方式。

按实际用户选择继续。推荐预选不是确认；拒绝替代选项就保持未提交。表单回传只是收到用户值，保存回传不是永久存储；以业务回执说明结果。draft_received应表述为“草稿已接收，正式预约结果尚未确认”，不能说草稿提交结果未知，也不能说预约已获准。

呈现失败时保留需求适配判断，本轮降级到可用的文字/原生方式，并说明未完成部分；不重复同一失败调用或冒充已展示、已提交。选型不增加真实业务操作权限。

遇到整单与单项、并列与Tabs、静态与交互等取舍，按需阅读 [典型示例](references/examples.md)。最终答案只呈现用户需要的信息，不暴露选型打分、内部字段或JSON协议；用户要求解释选型时再说明理由。
