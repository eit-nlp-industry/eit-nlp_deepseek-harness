# 能力与交付边界

在需要调用组件、处理接口缺口或解释结果时阅读。以当前工具说明、schema和接入配置为准；本技能不冻结某个本机版本的参数、URL、预设或模型。

|需求能力|核实什么|
|---|---|
|原生提问|是否有ask_user_question或同类工具；单选、多选、自由回答及等待方式|
|原生图片|资源可访问、图确实可见、视角和对象正确；替代文本不等于看过图|
|DynamicForm|可编辑字段类型、预填与当前值、实际提交方式、附件关联与回传|
|Steps|完整且有先后关系的步骤、每步说明、真实进度来源；只读展示不等于执行或可编辑|
|Chart|图型是否支持、真实数值与单位、标签/序列对齐、分析目的；图表不证明因果或预测|
|Tabs/Collapsible|分类可发现，切换或展开确有内容；不把隐藏详情当已经看过|
|SortableSequence|实际改序、完整条目、稳定标识和应用后回传；只改变清单外观不等于修改业务对象|
|Workflow|节点/分支/参数可编辑、文档保存回传、业务回执；不推定可执行、支持任意有向回环或永久记忆|
|MapPreview|点位、坐标、路线和缩放各自是否支持；自定义底图、点位详情、路线切换和实时位置分别确认|
|筛选/图表/实时看板|目录、事件及数据源都需存在；组件名称不证明筛选引擎、实时订阅或控制接口|

如果有render_ui，按当前schema选mode、组件及参数，不照搬别的部署的枚举或示例。需要的组件不在枚举中时，仅在当前工具文档明确支持其他接入方式后使用；否则说明缺口并降级。没有render_ui时不伪造可渲染JSON卡片。原生图片与文字不会因缺少动态组件而失去价值。

需求适配与可交付性分开：内容组织和用户操作决定采用哪种展示或交互；实际接口、资源和授权决定此刻能提供什么。暂时不可交付时，明确当前替代方案，而不是以一次故障否定需求的呈现价值。

确认和执行也分开：表单提交回传只代表收到用户值；工具结果确认的状态才可写入最终回复。草稿接收、预约批准、流程保存和流程执行是不同结果。未取得回执时明确哪些部分未完成，不虚构成功，也不否认已经确认收到的草稿。

display若依附最终回答而原生问题会阻塞当前回合，先完成图片/卡片展示，再收集确认，或选择已接通的同屏证据与确认模式。无图或图不可见时，不要求用户假装确认。

遇到生成/渲染失败，保留已知值、修订和附件；使用简明文字或原生问题完成可用部分，不重复同一失败调用。若没有可用的业务提交路径，明确保留草稿和未提交状态。降级不扩大业务权限，也不代替用户作不符合原要求的选择。

涉及表单按钮时，先读[按钮预设与回传](button-actions.md)。提交、保存、重置、跳过、放弃及继续新增等面向Agent的动作，应把意图与最新表单数据统一回传，由Agent决定下一步；链接导航及纯本地编辑另行处理。请求多个表单操作时，使用form_actions声明完整列表，由DSH生成独立同级按钮并统一绑定；不默认改为操作下拉框。仅在当前部署缺少此参数或确有失败且无法修正时说明限制并降级。

## 默认渲染与降级

命中正文中的简短文字、原生确认/补项、单图证据、静态地图、一次回执或用户指定格式等例外时，采用对应方式。其余已有足够事实且当前组件支持的需求，默认使用json-render，不把“没有交互”当成继续用纯文字的理由。较完整的报告、方案、分类资料、条目集合和多属性对照可用只读卡片、分区、表格或步骤展示。只需静态展示时不添加筛选器、切换、表单或按钮。

多项对照需传入真实条目和完整比较字段；报告/方案需传入概览、各部分事实、解释、证据和必要限制。按当前schema使用display，不能只传标题或一句摘要，让渲染服务补正文。界面能独立回答时可使用replace；必要解释留在文字中时使用supplement。按工具要求保留完整文字兜底，不以“界面已生成”代替答案，不向用户展示原始spec。

选用最简单的可用展示组件即可，不为使用json-render升级成整单编辑、流程控制或实时看板。已知缺少数据、组件、动作、资源或权限时先说明并澄清/替代，不用必然失败的调用试探，不发明接口。

已经调用而生成、渲染或资源展示失败时，本轮降级为完整文字或原生方式，并保留已有草稿、字段修改、对象及附件关联。只有存在明确可修正的诊断且工具允许时，才做一次有依据的修正调用；不能重复原请求、无限重试或轮换组件碰运气。仍失败或没有可操作诊断时直接兜底。界面失败不代表业务已提交或失败；分别报告已知的呈现状态与实际业务回执。

## 数据分析与Chart选型

对于已有真实数值的数据分析，当图表能更清楚地表达趋势、类别差异、排名或构成时，优先使用Chart并给出有依据的分析结论，不等待用户明确说“画图”。用户未指定图型时自行选择最贴合分析目的的一种，不单为图型偏好阻塞提问。用户指定方式仍优先；所需数据缺失、分析口径不明确或能力不支持时才澄清或采用可用替代。简短数值问答、单个指标及纯定性分析不为触发Chart而编造测量数据。

|分析目的|当前优先图型|条件|
|---|---|---|
|类别间数值比较、排名、不同组的同口径指标|bar柱状图|数值可比较、单位一致；比较排名时标签和值一起排序|
|时间序列的变化、走势|line折线图|保留真实时间顺序，标签与值对应，不把无序类别强连成趋势|
|同一整体内各部分的构成|donut环形图|仅一个序列，数值非负、合计大于0，各部分属于同一整体且口径不重叠|

当前已核实Chart仅支持bar、line、donut；不自造pie、scatter、heatmap等type。用户需要当前不支持的图型时说明限制，采用不歪曲分析目的的可用图或表格替代；不能把环形图称为已提供了指定的其他图型。不同量纲与定性属性混合的设备比较宜保留完整Table；可为价格等同口径数值附柱状图，不把价格、人数、距离和年限混成同一未说明尺度的数列。

工具schema支持时，在render_ui中列出components:["Chart"]以选择富组件目录，普通分析使用display；不要把bar/line/donut当成components名称。可将图表数据整理在business_data.chart等清晰位置，但这不是服务强制根路径。最终Chart.props使用type、可选字符串title、字符串数组labels、序列数组series；每个序列为{name:"指标名",values:[数值...]}。单位通过标题、序列名或配套说明表达，不向当前props添加未声明的unit、data或chartType。

当前labels为1—30个非空且不重复的字符串，series为1—5个名称不重复的序列，values为有限数值数组且长度与labels一致；donut只能有一个序列。labels、series及values按当前schema使用字面量数组，不用对象引用代替数组。Chart.series[].values中的元素必须是数值，不能套用Table单元格的字符串要求。具体数量及取值限制以当前部署schema为准；超限时按明确且说明的口径汇总或拆图，不静默截断。

标签、数值、单位和时间范围都取自已有材料；口径一致再比较。缺失不等于0，不擅自补0、插值或预测。计算占比、增幅或汇总时依据原始数值，并说明必要的计算口径及单位转换。图表与解读保留事实和推断的区别，不从走势直接宣称原因；没有真实数据就先澄清或做定性整理。调用时在user_query中加入所选图型及相关短类型约束，完整数据和分析依据仍放business_data。

Chart不替代必要的数字、约束、来源和结论，不能只给图而不回答分析问题。图表未覆盖的必要解释按工具约定用supplement保留；发生生成或展示失败时沿用一次有依据的修正及完整文字/表格降级规则，不反复试不同图型碰运气。

## 静态展示属性与绑定

业务数据可以包含对象、数组和数值；生成UI时必须逐属性服从当前组件schema。当前生成校验会先检查原始props，不能假定任何引用对象都会在检查前解析成字符串。即使{"$state":"/title"}最终可能指向字符串，将它直接放入只接受字符串的标题属性仍会失败。

|属性|当前要求|避免的写法|
|---|---|---|
|Section.props.title、description；Card.props.title|字符串，按schema可省略可选属性|整段业务对象、{text:...}、引用对象、null或{}|
|Steps.props.items|步骤对象的字面量数组|用一个引用对象代替整个items数组|
|Steps.props.items[].title、description|title为字符串，description为可选字符串|把整个步骤或绑定对象当标题/说明|
|Table.props.columns|字符串数组，如["型号","价格"]|Ant Design式的{title,dataIndex}列对象数组或引用对象|
|Table.props.rows|二维字符串数组，每行对应列顺序|业务对象数组、数值单元格或以对象引用代替行/表格|

向这些属性填写已提供的文本或明确的字符串叶字段。原数据为数值时保留business_data中的数值类型，向当前Table单元格写入时再按事实格式化为字符串；不把业务对象整体JSON.stringify成可见内容，也不补造金额、单位或结论。Steps每步title必须有事实来源；可选说明不存在时省略，不用{}或null占位。Table对齐列数与每行单元格数量，多种连接方式等列表可据原文合并成可读字符串。

只读说明、报告和比较没有必要为固定标题和正文增加动态引用。仅在当前schema明确允许相应表达式、状态来源正确且校验链路支持时使用。Text等其他属性可以有不同规则；Select.options、DynamicForm.fields、表单value和事件payload本来可能需要对象/数组，不能据此一概拍平或禁止绑定。可编辑表单仍须读取用户修改后的当前状态。

调用使用Section/Steps时，可在user_query附加：“Section标题、说明及Steps各项标题、说明使用字符串字面量，Steps.items使用数组，不使用引用对象。”使用Table时，可附加：“Table.columns是字符串数组，rows是按列对应的二维字符串数组，不用列定义对象或业务对象行。”按实际组件选择短约束，不把整份Skill塞入布局参数或挤掉必要布局信息；所有内容事实仍放business_data。

遇到invalid_props时区分类型问题与数据缺项：expected string, received object须检查是否误用整段对象、嵌套文本或状态引用；expected array须检查数组位置。仅拿到诊断、未见失败spec时，不声称已直接修复该spec；根据诊断约束一次修正请求，保留原事实。没有足够信息修正或仍失败时降级；不能把重试成功当作已定位先前对象的具体来源。

## 步骤条的适用范围

3个及以上有明确先后关系的操作步骤优先使用Steps；这是呈现偏好，不是任意列表的数量阈值。1—2步或用户明确要求简短文字时用文字；并列建议、事项清单和比较项不套用。步骤很多时保留内容和顺序，用分组、简短标题或纵向展示降低阅读负担，不为凑组件删掉步骤。

Steps是只读步骤序列，不默认提供执行、编辑、调序或业务提交。只要排好事项顺序的结果用文字；用户直接调整顺序并应用时考虑SortableSequence；编辑节点、参数或条件分支时考虑Workflow。不要为满足步骤条偏好生成流程编辑器或表单。

先根据真实材料组织步骤标题和必要说明，再调用render_ui；每步内容须进入business_data，不能只传标题让生成器补造。当前Steps使用props.items，每项为title及可选description、status，direction为horizontal或vertical，current表示当前步骤；具体参数以部署接口为准。Steps按当前工具说明走普通display即可，不向components添加未声明的Steps名称。

单纯讲解操作时，文案应明确是操作说明，不把默认高亮当成真实进度；不编造完成状态，也不擅自指定正在进行哪一步。只有任务实际提供进度事实时才设置相应状态。生成结果应保留全部步骤、先后关系和必要说明；无法交付组件时用完整文字步骤降级。

## 通用表单结构与自检

business_data保存真实业务数据和候选，user_query描述布局。组织通用表单时建议将字段定义集中在business_data.fields，其他业务对象、附件关联和稳定ID可保留在相应业务数据中；这是输入约定，不是服务对所有business_data强制执行的schema。最终DynamicForm的字段定义位于spec.elements.<表单ID>.props.fields。需要它时按当前工具说明选择表单mode与intent；DynamicForm不是可随意添加到components枚举的名称。

以下是当前已核实的DynamicForm字段约定；部署有不同接口时先查当前说明。字段使用type、key、label及可选value、disabled、placeholder；不向字段外层擅加options、default、required、rules、min或max。业务校验要求须使用实际支持的机制，不因把它写入业务数据就声称组件已执行校验。

|字段type|建议的value结构|注意|
|---|---|---|
|input|字符串|未知值可省略，不填造数据|
|inputNumber|数值|已知120写为120，不带货币符号或单位；不把未知金额补成0|
|date|日期字符串，如2026-12-10|仅使用已知日期，具体格式服从当前组件|
|daterange|{start_date:"2026-12-10",end_date:"2026-12-11"}|保存起止日期，不写成任意两元素数组|
|select|{options:[{value:"差旅",label:"差旅"}],default:"差旅"}|候选位于value.options，默认值是候选value|
|multipleSelect|{options:[{value:"投影仪",label:"投影仪"}],default:["投影仪"]}|默认值用数组，每项对应真实候选value|

表中的日期、金额和候选都是结构示例，不能变成用户事实。options每项须同时有字符串value和label；有实际业务ID时保留ID与显示名的区别。单选默认值用字符串，多选默认值用字符串数组；默认值来自已知选择且须属于候选。未选择时省略default，不为方便提交自选第一项。需要可选下拉时必须有真实候选；无候选时保留其他已知字段并澄清，或在业务允许时使用自由输入。

独立Select的候选位于props.options，props.value及绑定方式按其接口处理。不要向独立Select套value.options；也不要因为独立Select支持props.options就给DynamicForm字段加外层options。布尔确认等需求使用实际支持的原生问题或控件，不向DynamicForm自造checkbox等type。

调用前依次检查：

1. key非空且在本表单内唯一，沿用已有字段键和关联ID；type和外层键受当前组件支持。
2. value类型符合字段；选择字段options为非空对象数组，候选的value不重复，value和label均有事实来源。
3. default类型符合单选/多选，所有默认值属于候选，且没有把推荐项当成用户已选。
4. business_data保留真实字段、当前值、候选及附件关联；user_query不代替业务数据，不凭空补选项、金额或日期。

若能检查返回spec，再检查DynamicForm.props.fields中的候选与请求一致、默认值未丢失，提交读取当前绑定值而非初始快照。只有实际打开下拉或相应可见证据才能确认交互可用；拿到成功工具结果不代表已完成页面检查。

遇到unrecognized_keys或invalid_props，先区分是DynamicForm字段还是独立控件，再依据诊断的字段路径修正结构。未知外层options可能被严格schema拒绝，也可能在字段解析中丢失；而只剩value:"差旅"的选择字段即使通过schema，也可能显示默认值却没有候选。不要以删掉候选换取校验通过。按工具说明最多做一次有依据的修正调用；仍不可交付时保留数据并降级，不原样重试，也不向用户暴露协议诊断。
