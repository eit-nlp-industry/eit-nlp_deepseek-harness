研发—验收自动串通：方法、实现与问题记录

范围：modes/dev-acceptance-flow · 更新：2026-11-25
权威细则：README.md / TRANSITIONS.md
浏览器打开即可阅读；PDF 用「打印 → 另存为 PDF」。

一句话
研发与验收是两个独立会话。宿主用项目根 .flow 账本做状态机：研发写 submissions，验收写 reviews，宿主校验后改状态，再通过 outbox 把提示自动投进对方会话。

1. 怎么串通

1.1 角色

角色做什么不做什么
研发会话实现、自检；写 .flow/submissions/*.json不直接改 flow_status；通过前不进 PACKAGE
验收会话对照 prd_relpath；写 .flow/reviews/*.json不靠口头放行；blocked 不记账本违约
宿主 bridge校验、迁移、绑会话、投递 outbox不替代两边写业务代码
acceptance-data审计不驱动宿主放行

1.2 宿主每轮（约 2s）

auto-bind → pending-start → runHostOnce → ensureAcceptance → consumeOutbox

同进程 sessionController.prompt，避免 SDK 抢写锁。

1.3 闭环时序

开 development 会话（cwd=项目根，可选 .active-prd）
  → auto-bind 写 .flow（developing，acc=null）
  → 研发写出 submission
  → 宿主采纳 → awaiting_acceptance + prompt_acceptance
  → 懒建/绑定验收并投递
  → 验收写 review
       passed           → acceptance_passed + 交付提示 → 研发
       changes_required → remediating + 整改提示 → 原研发会话
       blocked          → awaiting_user（补材料后须重新送验）

三处文件交接： submissions →（outbox 到验收）→ reviews →（outbox 到研发整改/交付）。禁止聊天口令驱动。

1.4 Outbox

动作触发投向
prompt_development_start新绑定 / 换 PRD研发
prompt_acceptancesubmission 被采纳验收
prompt_development_remediationchanges_required研发
prompt_development_deliverypassed研发

投递优先 outbox 非占位 session id，其次才用 flow 绑定。

1.5 模块

模块职责
flow-host-bridge.js定时跑整条链路
auto-bind-development.js绑研发、PRD 归档切换
ensure-acceptance-session.js懒建验收、粘性保活
host-loop / transitions / validate扫盘、校验、迁移
outbox-consumer / prompt-templates文案与投递
active-prd / storePRD 选择与落盘/归档

2. 状态机硬约束

bootstrapping → developing → awaiting_acceptance
  → passed → acceptance_passed → delivering → delivery_completed
  → changes_required → remediating → 再送验
  → blocked → awaiting_user
  → 超轮次 → needs_manual

送验不能从 acceptance_passed 再发 initial。重复 event_id 忽略。

3. 粘性与多 PRD

规则效果
研发会话粘性协调中途不抢绑到同目录新研发会话
验收会话粘性已绑定且存活则不改绑、不新建
无送验不预绑验收developing 时不把旧验收提前绑上
PRD 自动归档空闲/已通过时 .active-prd 变化 → 归档旧 .flow 再开新轮；进行中拒绝

同目录多 PRD 是串行：一份活跃 .flow。并行请用两目录。改旧 PRD 程序：代码/git 还在，指回 .active-prd 开新轮即可。

4. 遇到的问题与解决

A. 整改进了另一个研发会话，又新开验收

原因：原会话短暂不在 list 时被抢绑；投递优先 flow.session；验收按「更优」改绑/重复 create。

解决：研发 sticky 状态集；验收 already_bound_live；resolveSessionId 优先 outbox；developing 不预绑验收。

B. 不能从 acceptance_passed 送验（换 PRD 后）

原因：旧轮已通过，改 .active-prd 不会自动开新周期；状态机禁止从已通过再送 initial。

解决：auto-bind 在非保护态发现 PRD 不一致则 archiveFlowRoot 再 bootstrap；start --force 同样先归档；送验用带后缀的新 project_id。

C. 验收会话列表混乱、绑错

解决：标题按 PRD stem；优先同 Workspace；懒创建 + 粘性。

D. review schema 不稳

解决：validateReview 规范化常见字段；非法仍拒收并记 journal。

E. 预览端口本机打不开

原因：临时端口未映射/未放行。

解决：改绑已映射端口（如 13186）；用毕停掉。
