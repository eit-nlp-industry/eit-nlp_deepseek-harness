# 七个技能串成一个连续故事

设定：李诺，学号尾号 0044，第 11 周。故事从 **2026-11-18 周三 12:05** 开始，到 **11-20 周五**结束。
七个东西全部用到：接驳车、待办安排、联系老师、订讨论室、点奶茶、订车票、校园卡余额自动化。

每个回合写三样：**用户提示词**、**该用哪个技能**、**应该的回应**（卡片字段写全，方便验收）。

> 全局规则：**一回合最多一张卡**。交互卡（表单）拆到多轮，展示卡合并成一张。脚本里每轮都按这个约束写。

---

## 第 1 轮 · 周三 12:05｜接驳车

**用户提示词**
> 刚下课，去食堂吃饭，接驳车还有多久？

**技能**：shuttle-wait

**应该的回应**
- 卡片：站点「教学实验楼」（依据：物理课 12:00 在教实 203 下课）；BUS-2 返回方向约 **3.5 分钟**；BUS-1 反方向约 9 分钟；假设「20km/h、每站停 30 秒、快照非实时」。
- 文字一句：提前 2 分钟到站台。

**验收**：有没有出卡、有没有写位置依据。位置错了（比如判成图书馆）说明课表没用上。

## 第 2 轮 · 周三 12:10｜排今天

**用户提示词**
> 帮我排一下今天下午和晚上。

**技能**：day-plan

**应该的回应**（周三课：AI 通识 8:00、物理 10:10、思修 18:30–21:20）
- 空闲窗：14:00–18:15（255 分钟）、21:35–23:00（85 分钟）。
- 卡片时间块：
  - 14:00–15:00 物理作业（11-18）
  - 15:10–16:10 线代作业（11-18）
  - 16:20–17:20 折腾小组 demo（11-18）
  - 21:35–22:35 高数小测复习（11-19）
- 未排上：线代小测、Science Talk（11-19）、阿拉伯视频（11-30），原因写清。
- 一句话解释：三件 11-18 到期的必须今天清，间隔 10 分钟、课前 15 分钟都已扣掉。

**验收**：块与块之间有没有 10 分钟；思修课前 15 分钟（18:15）之后有没有硬塞任务；会不会把 11-19 的任务排到 11-18 前面。

## 第 3 轮 · 周三 12:20｜问老师小测范围

**用户提示词**
> 明天高数和线代小测，帮我给沈老师和尹老师发邮件问一下范围。

**技能**：contact-teacher（两封，可以两轮）

**应该的回应**
一回合只能出一张卡，所以这里分三轮：

- 第一轮（展示卡，**合并**）：一张卡里两组「收件人 / 主题 / 正文全文」——沈捷（`shenjie@easterntech.edu.cn`，主题「关于高等数学 I 小测范围的确认」）和尹小龙（`yinxiaolong@easterntech.edu.cn`，主题「关于线性代数小测范围的确认」）。
- 第二轮（交互卡，**拆轮**）：单选「全部发送 / 只发沈老师 / 只发尹老师 / 先都不发」。
- 第三轮（展示卡）：发送确认，两封各一行：收件人、主题、发送时间（模拟）。

**验收**：正文是不是全文（不是“已起草”）；主题有没有带课程名；有没有编造用户没说过的事。

## 第 6 轮 · 周四 11-19 12:00｜余额自动化

**触发**：定时任务（不是用户说话），12:00 与 17:00 各一次。

**技能**：campus-card-check

**应该的回应**
- 余额 12.40 < 20 → 提醒卡：卡号尾号 4412、余额 12.40、最近一笔（11-19 08:10 校园超市 -6.80）、四个选项（200 / 100 / 50 / 先不充）。
- 同时发一封模拟邮件到 `linuo@easterntech.edu.cn`，主题带余额。
- 用户选 200 → 确认卡：新余额 212.40，标注模拟。

**反例也要演一次**：如果余额 212.40，这一轮**什么都不发**——不弹卡、不说话、不发邮件，只更新检查时间。

**验收**：余额充足时有没有忍住。

## 这个故事想验证的七件事

| 技能 | 验证点 |
| --- | --- |
| shuttle-wait | 位置推断有没有依据，等待时间算法对不对 |
| day-plan | 六条硬约束是否全部生效 |
| contact-teacher | 正文是否全文、主题是否带课程 |
| book-room | 缺字段是否先问、副作用是否标模拟 |
| order-milk-tea | 默认单人、多人问人数、两段配送 |
| book-ticket | 检索字段是否完整、是否索要卡号 |
| campus-card-check | 低余额提醒、余额充足时保持沉默 |

## 已知会翻车的地方

1. 模型可能读完 skill 却用文字回答，不出卡（**最常发生**）。
2. 卡片的「确定」按钮偶尔不生出来，只能回复编号。
3. `MapPreview` 地图卡基本生成不出来，接驳车建议只用站点卡。
4. 邮件、充值、出票、配送都是模拟，别把话说过头。
