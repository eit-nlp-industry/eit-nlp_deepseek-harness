# 跟随某个人

## 适用范围

用户明确指向一个人并要求跟随：「跟着他」「跟上前面那位」「跟着我」。一次只跟一个人。

- 用户没有明确目标（「跟着人走」）、画面里有多人且分不清时，先用一句话请用户说清是谁，结束本轮，不调用跟随工具。画面里有人明确指向某人时不算“分不清”。
- 不主动跟随，不因为「可能需要」就跟；跟丢后不自动改跟别人。

## 一、取画面和目标

- 只用最新的【环境观察】帧；没有可用画面，或目标不在画面里：一句话请用户让目标进入画面，结束本轮。
- 画面里有人用手指、手臂或身体朝向明确指向另一个人时，**目标是被指的那个人，不是指人的人**；这算明确指认，不要反问“跟哪一个”。
- 用户本人站在画面里指向某人时，同样按被指的人处理。
- 只有没有任何指向动作、多人又无法用衣着/位置区分时，才问一次“跟哪一位”，不猜。
- 记住这一帧的 `frame_id`。

## 二、框出目标的 bbox

用 0~1 比例（相对整帧宽高）框住目标本人：

- 框整个可见身体（头顶到脚；被遮挡的部分不脑补），人贴边时向画面内侧留一点余量；
- 只框目标一个人，不把旁人框进来；
- 目标太小、只有背影或严重模糊：换下一帧，或结束本轮请用户靠近/重新指一次。

`frame_id` 和 `bbox` 只是内部参数，不要写进给用户的回复。

## 三、展示目标并调用跟随工具

1. 先展示目标：调 `annotate_target({ frame_id, bbox })` 把目标框出来、暂存本地，会拿到 `asset_id`（只给了路径时，文件名去掉 `.jpg` 就是 `asset_id`）；再用 `render_ui` 把这张带框的图显示出来：
   - `mode` 用 `display`，`answer_presentation` 用 `supplement`，`components` 用 `["Image"]`，`intent` 用 `rich_content`，`locale` 用 `zh-CN`，`scene` 用 `dog`
   - `business_data` 只放 `{"image":{"assetId":"<asset_id>"}}`
   - `user_query` 用固定写法：

   > 页面只放一个 Image，不要标题、正文、图注、卡片头或其它组件。Image 的 props 必须是固定值：src 用数据里的 image.src 字符串，alt 用 image.alt 字符串；不要使用 $state 引用，不要改写地址，不把整个 image 对象赋给 src。

   没有 `asset_id` 或渲染失败时，就用文字说明目标的位置。

2. 再调用跟随工具：调用 `mcp__robot__follow_person`。它的参数只有 `query` 或 `bounding_box`，二者互斥：
   - 有上一步的 `frame_id` 和 `bbox` 时，传 `bounding_box`：
     `{"image_id":"<frame_id>","x_min":bbox.x,"y_min":bbox.y,"x_max":bbox.x + bbox.w,"y_max":bbox.y + bbox.h}`（全部 0~1）。
   - 没有可用框、但有文字描述时，传 `query`，例如「穿红衣服的人」；不要同时传两个。
   - 工具报错或不受理：说明没跟成及原因，不谎称已经在跟随；
   - 受理后不要重复发起同一个目标。

## 四、文字回执「正在跟随」

工具受理后，只用一句自然的中文说明当前状态，例如：

「好的，正在跟着他。目标离开画面我会先停止并告诉你。」

- 回执这一轮不再调用 `render_ui` 或其他交互工具（图在展示那一步已经发过）；
- 用用户能听懂的说法点明目标（如「穿红衣服的那位」）和状态，不写 bbox、frame_id、task_id 等内部信息；
- 只回执一次；后续观察轮只在状态变化（目标丢失、停止、Job 终态）时说话。

## 五、跟随过程中的观察

每收到一轮【环境观察】：

- 目标仍在画面里：调用 `observation_no_action`，不说话；不要重复调用跟随工具。
- 明确看不到目标（完全离开画面，或连续两轮都没有）：先停止当前任务，再告知一次，这次跟随即结束并回到常规观察；不换人、不追别人、不自行重新选目标。
  1. 先调用实际挂载的停止工具（名称含 `stop`）；停止失败就如实说明，不再发起新的跟随。
  2. 用 `annotate_target({ frame_id })` 把当前画面原样暂存（**不带 bbox，不画框**），拿到 `asset_id` 后用 `render_ui` 显示（`components` 用 `["Image"]`，`business_data` 只放 `{"image":{"assetId":"<asset_id>"}}`，`answer_presentation` 用 `supplement`）；没有 `asset_id` 或渲染失败就用文字说明画面无法显示。
  3. 用一句话告知用户并留出接口，例如「目标已经离开画面，跟随已停止；如果还需要跟随，请重新指一下目标」。
  4. 说完结束本轮。无论用户是否回复，这次跟随都到此结束：不追问、不重复提醒、不强迫用户重新指认。之后的观察轮回到预设的通用观察规则，不再和跟随任务绑定——没有值得处理的变化就调用 `observation_no_action`，需要沟通或执行再按规则处理；不要因为之前跟丢就自行重新开始跟随。
  5. 用户之后重新指认时，再按新目标重走第一到三步。
- 跟随工具返回需要用户选择（例如目标丢失后的等待/停止选项）：按返回内容转成一句中文问题，只问一次；用户不答复就不再追问，回到常规观察，不臆造选项。

## 六、停止和换人

- 用户说「别跟了」「停下」「不用了」：调用实际挂载的停止工具（名称含 `stop`），成功一句确认，失败说明原因。
- 用户换目标（「跟旁边那个」）：先停止当前跟随，成功后再按新目标重新走流程，不并发两段跟随。

## 约束

- 不把 bbox、frame_id、task_id 等内部信息说给用户；
- 不使用 bash / 终端 / 命令行工具；文件操作和展示只用已挂载的工具（`annotate_target`、`render_ui` 等）；
- 跟随 Job 的终态按预设规则原文输出；不调用 `get_task_status`，不无限轮询；
- 目标丢失时先停止并告知一次，这次跟随即结束；之后回到常规观察，不反复要求重新指认，也不猜测目标去了哪里。
