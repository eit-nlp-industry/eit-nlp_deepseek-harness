# 行程安排

## 什么时候用

用户要把几个地点或几件事排个先后（「安排一下」「先去…再去…最后…」「今天怎么走」）时用。只有一个地点、直接让带路的，走 `lead-route`，不用这里。

## 先排内容

- 从用户的话里拆出站点和要做的事，按他说的顺序排；他没说的不要自己补。
- 先按用户说的把日程**排出来、渲染出来**，不要卡在查地点上：地点可以查一次地图，查不到也照样放进日程、标一句「待确认」，不要反复查、也不要因为某个地名对不上就不出计划。
- 时间、开放、活动冲突可以查知识库补细节；拿不准的同样标「待确认」。
- 渲染完再问要不要补/改；不要一上来就追问地点，让用户先看到整份安排。

## 渲染

用 `render_ui` 出三块内容：已选路线（可拖排序 + 确认按钮）、可选景点（表单勾选）、每个站点的详情（可展开）。文字里仍要有一两句可朗读的说明。

### 交互能力边界（按宿主实际实现，不要假设更多）
- 只有三种事件会真正回传给 Agent：表单提交 `form.submit`、排序确认 `route.order.apply`、流程保存 `workflow.save`。其余自定义按钮（例如每项旁边的「加入路线」）不会回传，等同于装饰，禁止使用。
- `SortableSequence` 只能拖动排序，没有内置删除按钮；`route.order.change` 这类拖动事件不会回传。
- 点击列表项弹出详情没有事件支持；要展示详情用 `Collapsible` 或 `Descriptions` 就地展开。

### 1. 已选路线
- `mode` 用 `display`，`answer_presentation` 用 `supplement`，`intent` 用 `rich_content`，`locale` 用 `zh-CN`，`scene` 用 `dog`
- `components` 用 `["SortableSequence", "Collapsible"]`
- `business_data`：`{"title":"<日程标题>","items":[{"id":"s1","title":"<站点>","detail":"<看点>","stay":"<建议停留>"}],"confirm":{"label":"确认这个顺序"}}`
- 一个站点一项：`title` 写地点，`detail` 写看点和讲解重点，`stay` 写建议停留时间（标「约」）。
- 配一个按钮，`on.press` 的 action 用 `route.order.apply`，payload 里的 `order` 用当前 items 的 id 顺序；用户点它就会把新顺序回传给我。
- 每个站点再加一个 `Collapsible`，标题是站点名，内容是 `detail` 和 `stay`，相当于「点开看详情」。

### 2. 可选景点（加站/删站都走表单）
- 想加站时，用 `mode` `form`、`intent` `generic_filters`（多选）或 `generic_pick_one`（单选），`business_data` 里放真实候选（`id` + 名称 + 一句说明 + 是否待确认）。
- 表单必须有可见可用的提交按钮；提交内容会作为用户消息回来，我再按勾选结果重排路线。
- 想删站时，同样用多选表单列出当前站点，让用户勾选要保留的，提交后我重排。不要假装 `SortableSequence` 项上有删除按钮。
- 候选只能来自 `search_ragflow_semantic_map` 的真实锚点；锚点存在不代表对游客开放，未确认开放的候选在说明里标「待确认」。

### 3. `user_query` 写法
> 用 Card 展示 title；下面放 SortableSequence，items 直接使用数据里的数组，不要增删改写；每个站点用 Collapsible 展示 detail 和 stay；底部放一个「确认这个顺序」按钮，点击时发出 route.order.apply，order 取 items 的 id 顺序。不要增加其它按钮。

渲染后用一句话请用户确认，比如「顺序可以吗？想加站点，我出个勾选清单给你选」。

## 用户要改

改顺序、加站点、删站点、改时间，都按新内容**重新渲染同一个组件**：已确认的项保留，别只回文字。改完再问一次确认。

## 确认之后

- 先问一句「要现在带路吗？」，不要直接出发。
- 用户说去：按 `lead-route` 从第一项开始，到一站再走下一站。
- 用户说不去：保留这份安排，等他再说。

## 注意

- 卡片只是计划，渲染不等于出发，也不等于预约；本阶段没有预约工具，需要预约时按 `school-info` 只说明官方渠道，不承诺代办。
- 顺序以用户为准，不要自己调整。
