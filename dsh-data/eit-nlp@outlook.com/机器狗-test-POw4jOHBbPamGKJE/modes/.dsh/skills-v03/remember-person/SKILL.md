# 记人流程

## 触发

用于「记住我」「记住这个人」「记一下他」这类**记人**请求。只使用真实挂载的工具：`annotate_target`、`render_ui`、`remember_person`、`observation_no_action`。不使用表单。

## 第一步：选帧并确定 bbox

「有照片」指：最近的【环境观察】消息里有一张能看清目标人物正脸的画面，并且能取到它的 `frame_id`。用户单独发来的图片不算，因为记人工具只认观察帧。

**没有照片时**：告诉用户需要等机器狗在画面里看清本人，然后结束本轮。不要展示确认、不要调用 `remember_person`、不要用描述代替照片。

**有照片时**：记下 `frame_id`，并按下面的口径确定 `bbox`（0~1 比例）：

- 以头高 H 为单位，框高约 1.5~1.7H、宽约 1.7~1.9H，头顶留约 0.1H；
- 框头部加部分肩膀，不框全身、不框手和脚；
- 目标贴边时向画面内侧留一点余量；目标太小、背影、严重模糊时换下一张，或结束本轮。

## 第二步：在聊天里展示并请用户确认

1. 调 `annotate_target({ frame_id, bbox })` 把目标框出来、暂存到本地。结果里会带 `asset_id`，就是这张图在渲染目录里的标识；如果只给了路径，把文件名去掉 `.jpg` 就是 `asset_id`（不要带扩展名）。
2. 用 `render_ui` 把这张图显示出来（图片一律走 render）：
   - `mode` 用 `display`，`answer_presentation` 用 `supplement`（图旁边还要留确认的话）
   - `components` 用 `["Image"]`，`intent` 用 `rich_content`，`locale` 用 `zh-CN`，`scene` 用 `dog`
   - `business_data` 只放 `{"image":{"assetId":"<asset_id>"}}`，不要加标题、说明或别的字段
   - `user_query` 用固定写法：

> 页面只放一个 Image，不要标题、正文、图注、卡片头或其它组件。Image 的 props 必须是固定值：src 用数据里的 image.src 字符串，alt 用 image.alt 字符串；不要使用 $state 引用，不要改写地址，不把整个 image 对象赋给 src。

3. 再用一段文字写清：画面里是哪一位、姓名、facts（只写用户说过的内容），最后问「确认这个名字和信息吗？不对请直接说正确的名字/信息」；
4. **不用表单**（`render_ui` 只用 `display`），这一轮也不调用 `remember_person`；
5. 结束本轮，等用户文字答复；
6. 工具没给 `asset_id`（旧版工具）时，直接用文字说明「画面里是哪一位（位置/衣着）」并请用户确认，不强行展示。只要结果里有 `asset_id`，就必须用 `render_ui`。

## 第三步：按用户答复保存

- 用户确认（「对」「是」「确认」等）：调用 `remember_person`，**沿用上一步的 `frame_id` 和 `bbox`**，姓名和 facts 用确认过的：

```
remember_person({
  frame_id: "<上一步的 frame_id>",
  bbox: { x: 0.42, y: 0.12, w: 0.16, h: 0.20 },
  name: "<确认过的姓名>",
  facts: ["<确认过的基本信息，逐条>"]
})
```

- 用户更正姓名/信息：用更正后的值直接保存；更正内容不完整时再问一次，不猜；
- 用户取消（「不用了」「算了」）：不保存，一句「好的，这次不记了」结束；
- 工具提示帧不存在或已过期：说明这次没能保存，请用户等下一次观察，不要改用别的帧。

## 第四步：回执

保存成功后只回一句「已记住」，可以带上确认过的姓名；不重复展示图片，不谎称已保存。

## 约束

- 不编造姓名、不推断身份、不与他人比对；
- 一次只记一个人，多人分别走一遍流程；
- 不把内部字段、frame_id、bbox、attachment id 等技术细节写进给用户的回复。
