# 行程安排

## 什么时候用

用户要把几个地点或几件事排个先后（「安排一下」「先去…再去…最后…」「今天怎么走」）时用。只有一个地点、直接让带路的，走 `lead-route`，不用这里。

## 先排内容

- 从用户的话里拆出站点和要做的事，按他说的顺序排；他没说的不要自己补。
- 先按用户说的把日程**排出来、渲染出来**，不要卡在查地点上：地点可以查一次地图，查不到也照样放进日程、标一句「待确认」，不要反复查、也不要因为某个地名对不上就不出计划。
- 时间、开放、活动冲突可以查知识库补细节；拿不准的同样标「待确认」。
- 渲染完再问要不要补/改；不要一上来就追问地点，让用户先看到整份安排。

## 渲染

用 `render_ui`：

- `mode` 用 `display`，`answer_presentation` 用 `supplement`（卡片旁边还要问确认）
- `components` 用 `["SortableSequence"]`，`intent` 用 `rich_content`，`locale` 用 `zh-CN`，`scene` 用 `dog`
- `business_data` 长这样：

```json
{"title":"<日程标题>","items":[{"id":"t1","title":"<站点>","description":"<时间/事项>"}]}
```

- 一个站点一项：`title` 写地点或事项，`description` 写时间和要做什么；数组顺序就是执行顺序。
- `user_query` 用固定写法：

> 用 Card 展示 title，下面放一个 SortableSequence；items 直接使用数据里的数组，不要增加或改写；不要额外增加内容或按钮。

渲染后用一句话请用户确认，比如「顺序可以吗？要改直接说」。

## 用户要改

改顺序、加站点、删站点、改时间，都按新内容**重新渲染同一个组件**：已确认的项保留，别只回文字。改完再问一次确认。

## 确认之后

- 先问一句「要现在带路吗？」，不要直接出发。
- 用户说去：按 `lead-route` 从第一项开始，到一站再走下一站。
- 用户说不去：保留这份安排，等他再说。

## 注意

- 卡片只是计划，渲染不等于出发，也不等于预约；需要预约的站点走 `school-info` 的预约流程。
- 顺序以用户为准，不要自己调整。
