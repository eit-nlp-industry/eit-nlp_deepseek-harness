# 运动

任务的核心是让机器狗**换位置**时，按本 Skill。

## 工具

常用：`navigate` / `move_to` / `follow_person` / `stop`，以及定位（`get_phone_location`）、地点查询（`query_place`）、运动轨迹（`get_motion_track`）与示意地图。

## 两套坐标

- **行动**（真机）：`navigate` 只吃 `anchor_id`。去用户身边 → `get_phone_location` 的 `anchor_id`；去命名地点 → 语义地图检索的 `anchor_id`。
- **展示**（MapPreview）：只用平面示意坐标（0–100）。用户点用 `get_phone_location` 的 `x,y`；示意点（如图书馆、起点）用 `query_place`；狗的轨迹用 `get_motion_track`。与米制 / `anchor_id` 不混用、不换算。

## 出图规则

两类开跑前置，不要混用：

- **按地点 / `anchor` 开跑（`navigate`）**：每次开跑前先出实时示意地图。步骤：取本段平面点 → `get_motion_track` → 加载 `json-render`，读其 **`references/map-preview.md`** 后 `render_ui` → 成功后再 `navigate`。图上不要标起点，狗只靠实时图标；界面只要地图本身。未成功出图时只说明原因，不开跑。`move_to` / 视觉锁定类运动不调地图、不调 `get_motion_track`。
- **视觉对象锁定类开跑**（必须以画面里的具体人/物为对象才能动，例如跟人走、靠近被指的对象；不是按 `anchor` 去命名地点）：见下节，开跑前先出示**带框**锁定图，不走地图。

## 视觉对象锁定

凡本段运动必须从【环境观察】锁定具体对象再开跑时（跟人、靠近指定对象等）：

1. 看不清、多人分不清、没有可用帧 → 一句话问清是谁/哪个，**不要猜，不开跑**。
2. 能锁定 → 用本轮 `frame_id` 与目标 `bbox` 调 `annotate_target`（**要带框**）→ 拿到 `asset_id` → 加载 `json-render`，按其「纯图」配方 `render_ui`（只要 `Image` + `assetId`，不要界面内标题/说明）。
3. 若本段目标来自「段落后评估 · 可指认目标」且尚未得到用户确认：出图后**等确认**再开跑；用户已确认同一目标则可直接开跑。其它开跑（用户当场点名跟谁）出图成功后即可开跑。
4. 出图失败：如实说明，不开跑；不要假装已经锁定。
5. 同一锁定目标不要反复出图；用户换对象时先 `stop`（若已在跑），再按新对象重走本节。

## 出发前

1. 看清要去哪里或跟谁/哪个对象；多段或「到点再看是否符合」时，先确立候选与成功条件（见「段落后评估」）。缺关键信息时一句话问清。
2. 按地点行动：用「两套坐标 · 行动」取 `anchor_id`；查不到就说明。按画面对象行动：先完成「视觉对象锁定」。
3. 出发前参考 `self_check` 等真实返回；能否开跑以任务忙闲与工具结果为准。
4. 本段是 `navigate`：先完成地图出图规则再开跑。

## 开停与 Job

1. 用已挂载的运动工具开跑；受理（如 `status: running`）不等于到达。
2. 到达、失败、取消以后台 Job 终态通知（或工具明确给出的终态）为准。未终态前不声称到了，不开下一段导航。
3. 用户换目标或明确暂停：先 `stop`，成功后再开新运动。
4. 失败或取消：说明卡在哪，再按用户意图继续。

## 观察：两类时机

【环境观察】按任务阶段分流，不要混用：

| 类型 | 何时 | 做什么 |
|------|------|--------|
| **运行中监控** | 当前运动 / 跟随等 Job **尚未终态** | 核对契约是否还成立；偏离则中断并交代 |
| **段落后评估** | 当前段 Job **已终态**，且任务需要「到点看是否符合」 | 用最新帧对照用户条件做验收；再决定收束或换下一候选 |

途中路不通、有危险等仍按**运行中监控**打断，不要等到点再假装验收。

## 运行中监控

导航、跟随等运动 Job 未结束时，【环境观察】只用来核对当前这段能否继续：

- 画面仍表明按预期推进（目标还在、路可走）→ `observation_no_action`，不重复下发同一运动。
- 画面证明已偏离预期、做不下去（目标离开、关键对象没了、明显过不去等）→ **不要**当没事静默；按下面「偏离时出依据帧」处理。不擅自换人、换终点，也不在此时用「换候选」代替打断。

### 偏离时出依据帧

1. 该停就先 `stop`。
2. 用本轮【环境观察】的 `frame_id` 调 `annotate_target`（**不传 bbox、不画框**），拿到 `asset_id`。
3. **先**用一句短中文说明卡在哪（或验收结论），**再**加载 `json-render`，按其「纯图」出图：`components: ["Image"]`，`business_data` **仅** `{"image":{"assetId":"…"}}`。**禁止**在界面里加 `title` / `reason`（那会和聊天重复）。出图失败就如实说，文字总结仍要有。
4. 等用户或 Job 终态；不要只出图不说话。

## 段落后评估

适用于：用户要找「符合某条件的地方/对象」，需要到点看画面再决定是否换下一处（具体清单与成功条件以**当次用户表述与工具结果**为准）。

### 三个槽

- **候选**：任务开始时（或用户改口时）确立一份集合；来源只能是用户点名、工具/检索返回、已确认的计划。开跑与换点只取其中**尚未尝试**的项；中途不凭空发明新一类候选。
- **验收**：本段 Job 终态后，用**本轮最新观察帧**对照用户说清的成功条件，裁决为满足 / 不满足 / 无法确认。满足才算找到；无法确认不要当成满足，也不要当成「去下一个」的借口——先短说明看不清或请用户补条件。
- **耗尽**：没有尚未尝试的候选，或用户取消 / 收窄后集合为空 → 停止换点，一句说清试过的结论与为何停下，等用户。

### 验收出图分两档

先认清本轮验的是哪一类（不要一律无框）：

| 档位 | 验什么 | 出图 | 满足后 |
|------|--------|------|--------|
| **场景属性** | 空/闹、通不通、有没有空位等，不指向某一个体 | 无框整帧（「偏离时出依据帧」） | 读 [after-acceptance](references/after-acceptance.md) 判续跑 |
| **可指认目标** | 外貌/衣着/描述指向的人 or 物 | **带 bbox** 指认图；细则见 [target-acceptance](references/target-acceptance.md) | 只要告知 → 短报即可；还要跟人/靠近等 → **等确认**后再开跑 |

### 流程

1. 出发前（或改口时）记下候选集合、成功条件，以及验收档位（场景属性 / 可指认目标）；条件不清先问一句。
2. 每段按开跑前置出图后前往**一个**未尝试候选；在路上按「运行中监控」，不要提前验收。
3. 该段 Job **成功到达后必须验收**：**禁止**用 `observation_no_action` 跳过。**无论**满足 / 不满足 / 无法确认：先短说裁决，再按上表出图（纯图、无界面标题）。禁止只凭文字不下图，也禁止只出图不说话。出图失败则如实说明，文字裁决仍要有。
4. **场景属性 · 满足** → 短报后**必须**读 [after-acceptance](references/after-acceptance.md) 判续跑；禁止未读就结束或发明无关选项。  
   **可指认目标 · 满足** → 按 [target-acceptance](references/target-acceptance.md)：告知则结束等待；有后续动作则等确认后再走「视觉对象锁定」。
5. 不满足且未耗尽 → **先完成第 3 步出图与短报**，再取下一未尝试候选走开跑前置并开跑；不必征求「要不要去下一个」。禁止跳过依据图直接去下一点。
6. 耗尽或用户取消 → 若本段刚验收过仍须先有依据图（若尚未出）；再停止并说明，等待用户。

用户改口（换条件、删候选）：以最新表述更新槽与档位；已尝试过的是否重试听用户；未说则不默认重跑已失败项。

## 多段移动

一段未完成前不要开下一段：仅在上一段 Job 成功之后，再开下一段。下一段若是 `navigate`，仍按「出图规则」重新出图后再开跑。

- **行程已定**（用户一句话说清全程，如「来接我再去图书馆」）：上一段成功后**直接**开下一段，只短报进度，**不要**再问「要不要继续去某某地」。后台到达通知进新一轮时仍按原行程续跑。计划含糊、用户改口、明确暂停或上一段失败时，才开口确认或改计划。
- **到点验收类**：上一段成功后先走「段落后评估」。不满足则换候选或停下；**场景属性 · 满足**后的续跑以 `after-acceptance` 为准；**可指认目标 · 满足**后的确认与开跑以 `target-acceptance` +「视觉对象锁定」为准。不要自动改去未纳入候选的新地点。

## 展示

- 地点开跑：`render_ui(MapPreview)` 仅作 `navigate` 前置。
- 视觉对象锁定开跑、可指认目标验收：带框图。
- 运行中偏离、场景属性验收（含不满足换点）：无框图，按「偏离时出依据帧」。
- 其它进度示意：加载 `json-render`，按其非地图配方调用。

## 说话

短句说明进度、验收结果或阻塞即可。验收/依据图：**先**聊天短总结，**再** `render_ui` 纯图（界面不要标题块）。开跑前若已说清要去做，工具返回 `running` / 已受理后**不要**再复述同义进度；仅失败或有新信息时再说话。行程已定的中途点：报一声「到了，接着去…」并开下一段。运行中偏离或候选耗尽：文字与出图都要有，文字只交代一次，不连环催。
