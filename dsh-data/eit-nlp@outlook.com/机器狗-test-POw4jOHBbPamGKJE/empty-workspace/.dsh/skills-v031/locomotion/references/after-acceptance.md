# 验收之后有没有下一步

**场景属性**到点验收**满足**后必读（且已按主 Skill 出过本段无框依据图）。可指认目标（找人/找物指认）不走本文件，见 `target-acceptance`。先判定还要不要继续动，再分支。

## 先判定意图

按当次用户表述归类。**找满足条件的地点**且未明确说只要看看/不用带路 → 默认 **供用户去用**，短报后立刻接人带去，**不要**问「要不要回来接你」。

| 类型 | 如何辨认 | 验收满足后 |
|------|----------|------------|
| **供用户去用** | 找安静/有空位等可用地点，或说了「我想去…」「看书/办公」等 | 立刻「接人再带去」 |
| **取物带回** | 去某处把东西取回来 | 读 [carry-delivery](carry-delivery.md)，不要把到达当成已经取到 |
| **只探点** | **明确**只要确认、看一眼、不用带路 | 短报结束；不再开跑 |
| **行程已写明** | 一句话已定好多段 | 走主 Skill「行程已定」 |

不要发明「进去占座」「回起点等你」等选项。仅当原话与「找地方 / 取物 / 探点」都对不上时，才一句问「回来接你带过去，还是只要结果」。

## 供用户去用（接人再带去）

1. `get_phone_location` → 出实时地图 → `navigate(用户 anchor_id)`。
2. 再用**刚验收通过**的那一个候选的 `anchor_id` 出图 → `navigate`（不重新找候选、不换点）。

上一段成功后直接下一段，短报进度即可。

## 取物带回

不要在这里直接回用户。到达、核验、确认、装载、回程和交付都按 [carry-delivery](carry-delivery.md)。确认和「已在背上」两件齐了才回；东西是否在背上、是否被拿走，只看观察帧。

## 候选与坐标（续跑共用）

- 真机 `anchor_id`：语义地图 / 用户点名 / 本轮已有结果；**不要**用 `query_place` 发现候选。
- MapPreview：地点已选定后再 `query_place(该地点名)` 取平面坐标。

## 不满足 / 耗尽

不进入上述续跑；按主 Skill（含不满足也先出依据图）换候选或停下。
