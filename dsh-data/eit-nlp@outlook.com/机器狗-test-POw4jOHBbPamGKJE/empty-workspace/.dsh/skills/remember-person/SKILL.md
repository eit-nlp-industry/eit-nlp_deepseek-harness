# 记人流程

## 触发

用于“记住我”“记住这个人”“记一下他”这类**记人**请求。只使用当前真实挂载且用途匹配的工具（`camera_look`、`remember_person`）。

## 前置

- 没有 `camera_look` 或 `remember_person` 时，直接说明当前无法记人，不要用其他工具拼凑。
- 目标身份以用户提供为准；用户没说名字就用临时称呼，不猜测、不编造。

## 流程

0. **登记观察需求**（观察正在运行时）
   - 调 `observation_require({ mode: "enrolling", ttlMs: 600000 })`，让后台锁定当前这个人、加密采样并静默其他人的停留通知。
   - 观察没在运行就跳过这一步。
1. **取画面**
   - 默认 `camera_look({source: "snapshot"})`，读快照目录里的图。
   - 只有用户明确要看“现在/实时”且视频源可用时，才用 `source: "live"`。
   - 记下返回的 `view_id`（形如 `v3`）。
2. **确认目标**
   - 图里能明确看到目标才继续；多人且无法区分时按「需要用户输入时」处理。
   - 目标太小、背影、严重模糊时说明拍不清，不要硬记。
3. **给 bbox（0~1 比例，不是像素）**
   - `x`、`y` 是左上角，`w`、`h` 是宽高，全部用**占图宽/图高的比例**表示（0~1）。
   - 框**头部 + 部分肩膀**：以头高 H 为单位，框高约 1.5~1.7H，宽约 1.7~1.9H，头顶上方留约 0.1H 余量。
   - 不要框全身、不要框手和腿；不要给像素值。
4. **保存**
   - `remember_person({view_id, bbox, name, facts, note})`。
   - `view_id` 原样照抄，不要自己拼、不要传 attachment id。
   - 保存后调 `observation_release()` 结束 `enrolling` 需求，让观察回落到 `standby_person`。
   - 保存成功后只回一句「记住了，以后我们就是朋友了」——不要附带询问“有什么困难/需要帮忙”之类的话，记人阶段不做需求询问。

## 用户自述的信息

- `facts` 写**用户自己说的稳定信息**，一条一件事，尽量保留原话。例如用户说“我是小王，做机器狗的，喜欢喝美式”：
  - `name: "小王"`
  - `facts: ["做机器狗的", "喜欢喝美式"]`
- 只记录用户明确说过的；不要推断、不要补全、不要编造。
- **不要记录外观衣着**（今天黑 T 恤、明天可能换一件），照片本身已经包含外观。
- `facts` 最多 10 条，每条一句短句。

## 裁剪验收（默认不做）

- 保存成功后**不要读回裁剪图**，直接用一句话告知已记住谁。
- 只有下面几种情况才读回检查一次：
  - 框明显偏小：`w` 或 `h` 小于 0.05；
  - 目标贴边：`x + w > 0.95`、`y + h > 0.95`，或明显被画面边缘切掉；
  - 本轮已经裁坏过一次、正在重试。
- 读回只用于确认，不要把它变成固定步骤，也不要在每次保存后都做。

## 参数约定

- `bbox` 用 0~1 的比例，不是像素；它本身就是裁剪范围，工具不会额外留白，想留边就把框给大一点。
- `view_id` 只在 10 分钟内有效；过期就重新 `camera_look`。
- 不需要也不应该传角度、视场角之类的参数——画面已经是普通图片，没有可调朝向。

## 需要用户输入时

- 画面里有多人且无法从上下文区分时，在最终回复里列出候选（位置、外观特征），直接结束本轮，不擅自选一个。
- 用户没给名字且需要区分时，问一个必要问题即可，不调用提问或交互工具。

## 约束

- 只做“记录”，不做“识别”：不判断此人以前是否出现过、不与已有照片比对、不推断身份。
- 一次调用只记一个人；多人分别记录。
- 头部被切、严重模糊、只有背影时不保存，换一张画面再试。
- 分辨率不足、人脸过小时如实说明“只能记住大概”，不要声称已能辨认。
- 不把内部字段、参数名、attachment id 之类的技术细节写进给用户的回复。

## 失败处理

- 画面里没人：说明未找到目标，结束本轮，不猜。
- `view_id` 无效或过期：重新调用 `camera_look`，再裁剪。
- bbox 超出图片范围或裁剪失败：调整框后重试一次；仍失败则说明原因。
- 保存失败：说明未能保存及原因，不谎称已记住。
