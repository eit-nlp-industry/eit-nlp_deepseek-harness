# 引导任务

## 使用条件

用户要求带路、引导、陪同前往或"带我去某地"时使用。只使用**实际挂载且用途匹配**的工具；工具名以当前工具目录为准，本 skill 只描述职责与顺序。

## 一、启动前

1. 解析目的地：用户给出的完整地点名、房间号或编号原样用于查询；泛化需求（"能休息的地方"）用需求描述查。
2. 判断可执行性：以自检类工具返回的电量、健康、在线、忙闲、执行资格为准；只有原始数值没有阈值时，不自行判定"电量充足"。
3. 多个候选无法区分时：在最终回复里列出候选（名称、必要场景），结束本轮，**不导航、不派工、不猜**。
4. 无候选、查询失败或能力不足时：如实说明，结束本轮。

条件全部满足后启动导航，不要反复确认"是否前往"。

## 二、持续观察责任

导航任务被受理后，直到任务成功、失败或取消，持续观察被引导人员是否仍在跟随。

每次收到【环境观察】时：

1. 确认画面中是否仍能看到被引导人员。
2. 结合最近连续图片，判断其是否继续移动、明显停下、逐渐落后或离开画面。
3. 不根据单张图片、短暂遮挡或一次姿态变化认定对方没有跟上。
4. 对方正常跟随时，调用 `observation_no_action`，不重复发送导航指令。
5. 连续画面明确显示对方停下、距离持续增大或离开画面时，调用实际挂载的导航暂停工具（当前部署为 `stop`，工具目录里名为 `mcp__robot__stop`）。
6. 确认暂停成功后，调用 `move_to` 靠近对方。`move_to` 支持用自然语言描述目标，直接写「对方的合理描述」，例如：
   `{"target":{"type":"description","text":"前方走廊里穿黑色T恤的人"}}`
   距离不必精确，靠近一次即可。**不得询问**，也不得说「等你跟上来」「你跟上来吗」「你还在吗」这类等待或提问的话。
7. 暂停或靠近已经发起后，不在后续画面中重复执行同一动作。
8. 用户确认继续后，从当前位置恢复原目的地。
9. 导航任务进入终态后，不再执行本节的跟随判断。

### 关于"连续"的判定口径

观察窗口可能是 1 帧，也可能是 2–3 帧，且帧间有间隔。因此"连续"指**跨多个观察窗口的多次判断**，而不是同一窗口内的几张图：

- 单个窗口内变化不明确 → `observation_no_action`，等下一窗口；
- 连续两个以上窗口都指向同一结论（停下/落后/离开）→ 才采取动作；
- 短暂遮挡、侧身、低头看手机都不算"没跟上"。

### 临时限制：只判断第一次暂停

> 这条是调试期的临时规则，验证通过后删除。

- 整个引导任务中，只允许执行**一次**"对方停下 / 落后 / 离开画面"的判断，以及随之而来的一次 `stop` + 一次 `move_to`。
- 判定依据：翻本会话历史，只要已经出现过一次你发起的 `stop`，就视为这次机会已用完。
- 机会用完之后：后续【环境观察】不再判断对方是否停下、是否落后、是否离开画面；无论画面如何，一律调用 `observation_no_action`，不再 `stop`、不再 `move_to`、不输出文字。
- 恢复导航只能由用户明确确认继续来触发；恢复之后仍然不再做暂停判断。

## 三、动作与边界

- 暂停用 `stop`、靠近用 `move_to`，各只做一次；已经发起后等待结果，不重复触发。
- `move_to` 的用法以**本 skill 为准**，不要被工具描述的文字带偏：靠近就是朝对方所在方向移动一段距离，不要求精确到达。
- 参数按工具目录里的实际 schema 填写；工具报参数错误时按错误信息修正一次，仍失败就说明无法靠近并保持暂停。不得改为询问用户，也不得等对方自己靠上来。
- 任务状态只以真实工具返回和后台 Job 通知为准；已受理不等于完成。
- 不因为"看起来对方跟上了"就宣称任务完成。
- 动作失败时停止后续步骤，说明失败原因，不静默重试。
- 引导过程中不启用与当前任务无关的自主行为（不闲聊、不识人、不记人）。

## 四、与用户沟通

- 启动时：一句话说明要去哪、已开始，例如「好，我带你去学术报告厅，跟紧我」。
- 暂停/落后时：不询问，也不发等待类的话（禁止「我先停一下，等你跟上来」这类）。暂停与靠近发起后，本轮**可以不说任何话**；需要说话时只说结果，例如「我过来了」。
- 靠近动作和话术不能互相矛盾：已经在靠近时，不得再让用户「自己过来」「跟上来」。
- 恢复时：一句话确认，例如「好，继续走」。
- 终态时：一句话说明到达或中止。

## 五、失败与异常

| 情况 | 处理 |
|---|---|
| 导航工具返回失败 | 停止后续步骤，说明未能开始/未能继续，不谎称已出发 |
| 暂停指令未确认成功 | 不执行 `move_to`，说明状态无法确认 |
| `move_to` 参数不被接受 | 按错误信息修正一次再试；仍失败则说明无法靠近，保持暂停 |
| 长时间看不到人 | 按"离开画面"处理，暂停后调用 `move_to` 靠近；不询问、不无限等待 |
| 任务被取消或用户要求停止 | 立即停止跟随判断，一句确认即可 |
| 工具能力不覆盖需求（如无法指定跟随时长） | 说明限制与默认策略，结束本轮，等用户决定 |
