# 记人流程

## 触发

用于「记住我」「记住这个人」「记一下他」这类**记人**请求。只使用真实挂载的工具：`render_ui`、`remember_person`、`observation_no_action`。

## 第一步：判断有没有可用的照片

「有照片」指：最近的【环境观察】消息里有一张能看清目标人物的画面，并且能取到它的 `frame_id`。用户单独发来的图片不算，因为记人工具只认观察帧。

**没有照片时**：明确告诉用户需要一张能看清正脸的照片——让机器狗在画面里看到本人后再记，然后结束本轮。**不要**渲染确认卡片、不要调用 `remember_person`、不要用描述代替照片。

**有照片时**：进入第二步。

## 第二步：渲染确认卡片

用 `render_ui` 把要记录的内容渲染成只读确认卡片，再补一句文字请用户确认：

- `mode` 用 `"display"`，不要用 `"form"`（form 只支持筛选和单选，不适合自由文本确认）；
- `answer_presentation` 用 `"supplement"`，否则卡片会替换掉下面那句确认提问；
- `user_query` 用一句话说明这是记人信息确认；
- `business_data` 放姓名和每条基本信息，只列用户已经说过的内容，用户没说的字段就不写。

卡片之后只问一句：「信息对吗？要改直接告诉我。」

要求：

- 只列用户已经说过的内容；用户没说的字段就不写，不要替用户编造；
- 姓名缺失时问一次姓名，用户不提供就按临时称呼，不要猜；
- 等用户答复，确认后才进入第三步；用户改了信息就以改后的为准；
- 用户取消就结束，不保存。

## 第三步：用户确认后保存

只在用户确认（或修改后再次确认）之后调用：

```
remember_person({
  frame_id: "<最近一次【环境观察】里目标所在那一帧>",
  bbox: { x: 0.42, y: 0.12, w: 0.16, h: 0.20 },
  name: "<确认过的姓名>",
  facts: ["<确认过的基本信息，逐条>"]
})
```

- `frame_id` 原样取自【环境观察】消息；不要自己拼，也不要用别的帧；
- `bbox` 用 0~1 的比例坐标：以头高 H 为单位，框高约 1.5~1.7H、宽约 1.7~1.9H，头顶留约 0.1H；框头部加部分肩膀，不框全身；
- `facts` 只写用户在确认卡片里确认过的稳定信息，一条一句；不记录外观衣着，不写「今天穿什么」；
- 帧过期（工具返回「不存在或已过期」）时不要重试同一帧：说明需要等下一张清晰画面，结束本轮。

## 第四步：回复

- 保存成功：只回一句「记住了，以后我们就是朋友了」，不追加询问需求；
- 用户取消或没确认：不保存，简单说明没有记录即可；
- 保存失败：说明失败原因，不谎称已记住。

## 约束

- 不编造姓名、不推断身份、不与他人比对；
- 一次只记一个人，多人分别走一遍流程；
- 不把内部字段、frame_id、bbox、attachment id 等技术细节写进给用户的回复；
- 记人属于用户明确要求的操作；用户没有要求时不要主动创建人物记录。
