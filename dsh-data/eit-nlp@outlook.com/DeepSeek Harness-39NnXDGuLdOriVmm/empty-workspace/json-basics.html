01

JSON 是什么

一种用纯文本描述数据的通用格式，不是编程语言，只是一套书写规则。 可以把它想成一张“栏目名 + 填写内容”的规范表格：左边是键，右边是值，程序按栏目名取值。

表格视角人看的
栏目名（键） 填写内容（值）
name 林小满
age 20
isMember true

一张表，三行数据。每行都是“栏目名 + 内容”。

JSON 视角程序读的
{
  "name": "林小满",
  "age": 20,
  "isMember": true
}

同一份数据，换一种写法。大括号表示“这是一张表”。

程序要取姓名，就按栏目名 name 去找对应的值；要判断是不是会员，就看 isMember。 键名相当于地址，值才是内容。

02

六种基本类型

JSON 只有六种基本类型。记住这张表，日常见到的 JSON 基本都能读懂。

类型 示例 说明
字符串 string
"你好"
双引号包住的文字。句子、名字、日期通常都写成字符串。
数字 number
20
直接写，不加引号。整数、小数、负数都可以。
布尔值 boolean
true
只有 true 和 false，表示“是 / 否”“开 / 关”。
空值 null
null
表示“这里没有内容”。它不等于 0，也不等于空字符串。
对象 object
{"name": "小明"}
花括号里的键值对集合。可以嵌套，装下一张更小的表。
数组 array
["A", "B"]
方括号里的有序列表。顺序有意义，可以放多个值。

日期没有单独的类型，通常写成字符串，例如 "2026-11-14"。

03

三个最常见的错误

新手踩坑率最高的三处。每一组都给出错误写法、正确写法，以及为什么会错。

错误 01

用单引号代替双引号

✕ 错误写法

{
  'name': '小明'
}

✓ 正确写法

{
  "name": "小明"
}

原因

JSON 只认双引号。单引号是 JavaScript 的写法，JSON 解析器会直接报错。

错误 02

最后一项多了一个逗号

✕ 错误写法

{
  "name": "小明",
  "age": 18,
}

✓ 正确写法

{
  "name": "小明",
  "age": 18
}

原因

JSON 不允许尾随逗号。逗号只用来分隔两项，不能用来结尾。

错误 03

键名不加引号，还顺手写注释

✕ 错误写法

{
  name: "小明",   // 姓名
  age: 18
}

✓ 正确写法

{
  "name": "小明",
  "age": 18
}

原因

键名必须加双引号；JSON 标准不支持注释。要说明什么，就单独加一个字段，把话写进值里。

!
自查小技巧

把文本粘进任意 JSON 校验器，它会直接指出第几行第几列出错， 比肉眼一行行找快得多。

记住三件事：双引号 · 逗号 · 键名
