# 样例 | 活动会场布置好了吗：让狗替我先走一圈

**目的：** 用到场后的实时画面，补足静态地图和筹备清单答不了的问题——指示牌是否挂好、签到台用品是否齐全、入口通道是否占道。

**主要能力：** 语义地图到会场 + 场内逐点移动观察 + 初检工单 → 整改确认 → 复核报告。

**场地与前提：** 仅演示「校园开放日 · 开场准备检查」；可用视频推流模拟现场，聊天中只说「现场画面」，不点名视频文件；不表述为真实现场验收或消防/结构认证。

---

## 用户侧三步

### 1. 下任务，狗先到会场

- **用户：**「帮我检查一下图书馆开场准备，会场布置好了吗？」
- **机器狗：**「正在前往图书馆。」→「已到会场，开始开场检查。」→「现在前往活动指示牌。」
- **界面：** 对话里只报位置切换；到位后再看现场画面，不宣称「已经检查完」。

### 2. 发现问题，出一张待处理工单

- **机器狗：**「已到达签到台，开始检查。」→「签到台缺用品，已登记。」→「现在前往入口通道。」→ 初检汇总后出工单。
- **界面：** Tabs「待处理事项 1 / 2」+ 证据图；表单含地点、处理人、整改说明；按钮「确认已整改」。
- **用户：** 点「确认已整改」（演示 mock，不向第三方真实派单）。

### 3. 整改后再走一圈，出报告

- **机器狗：**「现场确认已处理，开始复核。」→「现在前往签到台。」→「已到达签到台，开始复核。」→ 逐项复核后出报告。
- **界面：** 报告 Tabs（如「签到台·已整改通过」）+ 初检/复核短说明 + 证据图；一行整体结果，不要长篇 Markdown。

## 检验点

- **未到位不下结论：** 口头「已在签到台」不算数，必须等真正走到该点后再看现场画面。
- **未看到 ≠ 没有：** 模糊、局部、遮挡只能说「还看不清」；缺项要完整区域清楚才可登记。
- **先查完再出单：** 第一处缺陷只登记，等初检点都走完再出一张待处理工单。
- **工单可点、复核要重新走：** 「确认已整改」只表示演示上已处理；复核须再走到该点、看新画面，不能用旧图关掉问题。
- **演示边界：** 聊天不点名视频文件；结果不作真实现场验收或消防 / 结构认证。
