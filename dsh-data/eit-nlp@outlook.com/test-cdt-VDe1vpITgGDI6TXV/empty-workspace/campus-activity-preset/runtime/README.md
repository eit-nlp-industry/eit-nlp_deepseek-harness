# runtime —— 已确认方案快照

`plan_save` 把每次最终确认的方案写成 Markdown（带 YAML front matter）放到这里。

## 文件名

```
<UTC 时间戳>-<slug>.md        例：20261113-074501-plan.md
同秒重复保存时追加序号：      …-plan-2.md、…-plan-3.md
```

## 文件结构

```markdown
---
id: 20261113-074501-plan
title: 班级读书会 · 已确认方案
scene: 班级读书会            ← 活动场景，用于区分与检索
venue: 教学楼 302 教室        ← 场地，用于冲突检查
start: 2026-11-20 19:00
end: 2026-11-20 20:30
booking: 模拟预约成功（mock，未真实预约）
savedAt: 2026-11-13T07:45:01.000Z
---

# 班级读书会 · 已确认方案
（方案正文）
```

## 场地冲突

`plan_check(venue, start, end)` 会扫描已保存方案，判断同一场地的时间段是否重叠。
`plan_save` 也会在保存时自动检查，并在返回值里带上 `conflicts`。

判定规则：场地名（忽略大小写与首尾空格）相同，且 `start < 对方 end && 对方 start < end`。

## 调取方式

在「校园活动筹备助手」会话里说：

- 「看看之前保存的方案」→ `plan_list`，每行包含场景 / 场地 / 时段 / 预约状态
- 「打开 <编号>」→ `plan_get` 读取全文

## 说明

- 快照不随对话更新；改方案需重新确认并再保存一次。
- `booking` 是**模拟**结果，不代表真实预约。
- 删除文件不影响预设本身。
