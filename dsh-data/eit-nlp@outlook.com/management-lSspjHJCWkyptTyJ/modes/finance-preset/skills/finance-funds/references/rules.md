# 业务规则

名称以 `finance-funds` 本轮读到的字段列表为准。下面的词是在说明口径，不是允许值。对不上就用含义相同的线上字段，没有就停下来说明。

## 1. 计算口径

| 指标 | 口径 | 取数 |
|---|---|---|
| 共使用 | 该项目下**全部** `支出` 之和（退款为负数，自然抵扣） | 读 `共使用`（公式） |
| 剩余（现金余额） | 到账 − 共使用 | 读 `剩余金额`（公式） |
| 使用率 | 共使用 ÷ 到账 | 读 `项目费用使用率`（公式） |
| 实际到账金额 | 该项目下 `收入` 且 相关=是 之和 | 公式，只读 |
| 非项目收入 | 该项目下 `收入` 且 相关=否 之和（别人还钱、垫付收回） | 公式，只读 |
| 项目盈亏 | 到账 − **项目相关**费用 | 读 `实际到账金额` − `项目使用金额` |
| 项目相关费用 | 该项目的费用中「是否与项目相关 = 是」的金额和 | 读 `项目使用金额`（公式） |
| 科研/非项目支出 | 「是否与项目相关 = 否」的部分 | 读 `非项目使用金额`（公式） |

**优先读公式字段，不要自己重算。** 公式为 0 或空但明细明显有数据时，说明公式可能没配好：先告警，再用明细重算并注明「本次为手工计算」。

线上没有「项目盈亏」字段。已使用、剩余、使用率是公式，盈亏用 `实际到账金额` − `项目使用金额` 现算。记完费用回显时带上这一项。

## 2. 项目相关性

「是否与项目相关」与「经费来源 / 资金主体」是两件事：

- 钱从项目的某个经费来源出 → 只说明资金来源
- 这笔钱实际用于科研 → 可能不计入项目成本

所以不要用经费来源推断项目相关性。用户没说时把「是否与项目相关」留空，交给 `当前界面技能`。

收入方向同理：`收入` + 相关=是 才是「项目到账」；相关=否 是「非项目收入」，不进项目到账。

## 2.0 方向判断

本表只记项目经费的进出，方向只看一件事：钱是从项目出去，还是进到项目里。

「报销」是流程词，不是方向词。同一句「报销」，付款方不同，记法就不同：

| 谁付钱 | 有没有对应的原支出 | 记法 |
|---|---|---|
| 项目账户 → 个人 / 供应商 | — | **支出**（余额减）：财务报差旅、教授报耗材、付供应商 |
| 研究院 / 甲方 / 供应商 → 项目账户 | **有**（补的是某笔具体支出） | **支出填负数 + `冲销原单`**（余额增，同时冲减那笔成本） |
| 研究院 / 甲方 → 项目账户 | **无**（经费拨付、无对应支出） | **收入**（余额增） |

判断顺序：① 钱是项目付出去的吗？是 → 支出。② 不是的话，这笔钱是补某笔具体支出的吗？是 → 负数支出 + 冲销原单；不是 → 收入。

下面这组数字只说明四种事件怎么叠。表单上的余额用当前项目刚读到的 `剩余金额`，不要抄这组余额。

| 事件 | 谁付钱 | 记法 | 余额 |
|---|---|---|---|
| 研究院拨付 | 研究院 → 项目 | 收入 200,000（相关=是） | 200,000 |
| 财务出差报销 1 万 | 项目 → 财务 | 支出 10,000 | 190,000 |
| 教授买耗材 4 万 | 项目 → 供应商 | 支出 40,000 | 150,000 |
| 研究院报销回款 2 万（补那笔 4 万耗材） | 研究院 → 项目 | 支出 **-20,000** + 冲销原单 → 共使用 30,000 | **170,000**（使用率 15%） |

表单上要写出余额变化。财务靠这一行核对方向有没有记反。

### 另两个独立维度

| 谁垫的钱（→`人员`） | 用途（→`是否与项目相关`） | 金额列 | 相关 |
|---|---|---|---|
| 财务自己 | 项目耗材/差旅 | `支出` | 是 |
| 财务自己 | 个人物品（如确需从项目出） | `支出` | 否 |
| 老板 / 其他同事 | 项目开支 | `支出` | 是 |
| 老板 / 其他同事 | 非项目开支 | `支出` | 否 |

看到「给自己报销」不要判定为非项目，看到「给老板报销」也不要判定为项目。`人员` 填谁，和这笔钱算不算项目成本，没有关系。

录入者不是受益人。财务替别人录，`人员` 填垫钱的那个人，`创建人` 会自动记下是谁录的。

| 用户说法 | 记成 | 说明 |
|---|---|---|
| 报销（项目付钱给个人） | `支出` | 只看用途决定「相关」 |
| 研究院/甲方给项目报销 | 有原单 → `支出` 负数+冲销；无原单 → `收入` | 有原单时不要记成收入 |
| 垫付 / 代付 | `支出` | 我先把钱付了 |
| 项目拨款 / 经费到账 / 合同款 | `收入`（相关=是） | 钱进项目，且没有对应的原支出 |
| 供应商退款 | `支出` **负数** + 冲销原单 | 原路退回 |
| 我退回收到的钱 | `收入` **负数** + 冲销原单 | 原路退回 |
| 别人还我钱 / 收回垫付 | `收入`（相关=否） | 非项目往来 |
| 我借钱给别人 | `支出`（相关=否） | 非项目往来 |

付款方已经能对上 §2.0 的某一行时，按那一行记。对不上时，进出方向和「是否与项目相关」都留空，交给 `当前界面技能`。

## 2.1 退款与冲销

退款不是新类别，是某笔交易的逆向：

| 场景 | 怎么记 |
|---|---|
| 我付出去的钱被退回（供应商退款） | 新增 `支出` **负数**，`冲销原单` 指向原来那笔 |
| 研究院/甲方对某笔项目支出做报销、补偿 | 同上：`支出` **负数** + `冲销原单` 指向那笔支出 |
| 我收到的钱退回去 | 新增 `收入` **负数**，`冲销原单` 指向那笔收入 |

- 不要用「收入」记支出退款，也不要用「支出」记收入退回。方向不变，符号取反
- 退款是新增一笔，并让 `冲销原单` 指向原记录。不要把原记录的金额改小
- `冲销原单` 是自关联字段，能追溯哪些单被退过
- 一笔原单可以多次部分退款，净额由公式自动算

## 3. 项目状态

表里 `状态` 是公式字段，只读，不要写它：

| 条件 | 状态 |
|---|---|
| 剩余金额 > 0 | 正常 |
| 剩余金额 = 0 且 实际到账金额 = 0 | **正常**（项目还没到账，不算预警） |
| 剩余金额 = 0 且 实际到账金额 > 0 | 预警（钱到了但花完） |
| 剩余金额 < 0 | 超支 |

写完到账或费用后等 1–2 秒再读 `共使用`、`剩余金额`、使用率，否则会拿到旧值。

## 4. 项目匹配

用户给的是项目名，表里 `项目` 是单选：

1. 先按名称做包含匹配，忽略空格和「项目」后缀
2. 命中 1 条 → 直接用，并在表单里回显全名
3. 命中多条 → 把候选交给 `当前界面技能`，不要自己挑
4. 0 命中 → 表单上提供「新建：<用户说的名字>」。用户选了新建才走新建流程

### 启动资金

用户只说「启动资金」时，不要把它写成预算。让用户在本轮读到的选项里选定这笔钱算预算还是已经到账。选中预算才写入 `预算金额`。选中已到账另记一条 `收入`（相关=是）。

## 5. 费用类型

费用类型的可选项以本轮字段列表为准。把用户的口语对到其中一项：对得上就用那一项，对不上就留空。不要因为拿不准就选一个看起来像「其他」的选项。

## 6. 日期与金额

- 相对日期（今天、昨天、上周三）先换算成具体日期，表单上显示「昨天（具体日期）」
- 日期字段写毫秒时间戳，按会话时区当天 00:00
- 金额两位小数。正常交易填正数。退款填负数（见 §2.1）。用户说「退回来 / 退回」就是新增负数冲销，说「改一下金额」才是修改原记录

## 7. 重复判定

导入和录入时，以下四项同时相同视为疑似重复，先列出来让用户决定，不要直接写入：

同一人员 + 同一收支金额 + 同一申请日期 + 同一关联项目

## 8. 字段写入约束

| 类型 | 例子 | 能不能写 |
|---|---|---|
| 文本 / 数字 / 单选 / 日期 | 项目编号、收入、支出、费用类型、申请日期 | 能 |
| 双向关联 | 关联项目 | 能，值是该表的 record_id 数组 |
| 文本 | `人员`（原「报销人」） | 能，直接写姓名 |
| 附件 | 票据 | 能。先用 `scripts/upload_media.mjs` 换 file_token，值写成 `[{"file_token": "..."}]` |
| 双向关联（自关联） | 冲销原单 | 能，值是 record_id 数组，指向本表原记录 |
| 公式 / 自动编号 / 创建人 / 查找引用 | 共使用、实际到账金额、非项目收入、费用编号、创建人 | 不能 |
