# 动作手册

写出哪些字段、能不能写，由本手册决定。本轮有 `render_ui` 时，当前界面技能是 `finance-form`：留空，不要先追问，表单提交后才写入。没有 `render_ui` 时，当前界面技能是 `finance-text`：缺必填先问，文字确认后才写入。下面写「当前界面技能」就是这一份。

余额变化用刚读到的 `剩余金额` 现算，写成「当前剩余 → 记完后的剩余」。不要沿用规则举例里的 200,000 那组数字。

---

## §查

### 查询费用

1. 解析条件：人员、费用类型、日期范围、关联项目、收支金额区间。缺的不要补默认值
2. 读 `费用清单表`。记录不多时全量取回，再在这批记录里过滤；一次放不下就按条件缩小后重取，并说明省略了什么
3. 明细、合计和两句可以继续问的建议交给 `当前界面技能`。找不到就直说没查到，并建议放宽条件。标题用用户实际问的范围。表上带刚读到的项目、日期、金额；人员或费用类型不是这次的条件时，不要写进标题

### 资金概览 / 费用结构分析

1. 取项目表，再按项目看费用公式字段。口径用 rules §1，状态用 rules §3
2. 结论和各项目的预算、到账、已使用、剩余、使用率、盈亏交给 `当前界面技能`。有 `render_ui` 时，对比、趋势、占比由 `finance-form` 决定要不要配 Chart
3. 数字只用刚读到的值

## §增

### 记一笔费用

1. 从原话抽：人员、日期、项目名、金额、费用类型、是否项目相关、用途。记账方向只按 `rules.md` §2.0 和 §2.1。「报销」不是一律支出；研究院或甲方补某笔已有支出时，记负数支出并冲销，不要记成收入
2. `人员` 填这笔钱补给谁，和「是否与项目相关」分开判断
3. 匹配项目（rules §4），拿到 record_id
4. `资金主体` 取自关联项目的 `经费来源`，只给 `当前界面技能` 展示，不写入费用表
5. 交给表单的字段：资金主体、项目、人员、申请日期（相对日期旁写具体日期）、费用类型、收入或支出、是否与项目相关、说明、余额变化。退款再加冲销原单。单选值不在现有选项里时注明「将新增选项：X」。没识别到的留空
6. 表单提交后写 `费用清单表`：人员（文本）、申请日期、是否与项目相关、费用类型、`支出` 或 `收入`、说明、关联项目（record_id 字符串数组）。退款再传 `冲销原单`。`收入` 与 `支出` 只填其一
7. 等 1–2 秒后重读该项目行，回显公式算出的状态、使用率，以及盈亏（`实际到账金额` − `项目使用金额`）

### 新建项目

缺项目编号、经费来源、项目类型，或分不清启动资金是预算还是已到账时，留空交给 `当前界面技能`，不要先问。不要编项目编号，也不要把这笔金额直接写成预算。

信息齐全后：

1. 用 `项目编号` 全表搜索，重复就直接说，不要改名绕开
2. `项目` 是单选，新名称会自动新增选项。表单上写明「将新增选项：<名称>」
3. 表单提交后写入：项目编号、项目、项目类型、经费来源、预算金额、立项时间。`实际到账金额` 是公式，不写
4. 用户说的是已到账金额时，另写一条关联该项目的 `收入`（相关=是）。到账不要写进 `预算金额`

### 发票录入

1. 用户发图或 PDF，按票据上的文字抽取金额、日期、销售方、事由
2. 抽不到的字段留空，交给 `当前界面技能`
3. 剩下同「记一笔费用」：匹配项目 → 表单提交 → 写入
4. 路径用用户这条消息里已经给出的附件。不要自己在目录里找文件。然后执行 `node <skill>/scripts/upload_media.mjs <文件路径>`，用返回的 `file_token` 写入 `票据: [{"file_token": "..."}]`
5. 表单上写一行「将上传附件：<文件名>（<大小>）」。单文件不超过 20MB。上传返回 99991672 时说明缺 `drive:drive`，不要重试。删记录不会删掉已上传的云空间素材

## §改删

### 修改

1. 用 `费用编号` 或（人员 + 金额 + 日期）定位到唯一记录。多条命中就交给 `当前界面技能` 列出候选
2. 只把要改的字段和改前、改后交给表单
3. 表单提交后 update，只传变更字段

用户说「退回来」时走 rules §2.1，新增一笔负数冲销，不要把原记录的金额改小。

### 删除

当前连接没有删除工具。告诉用户需要到多维表格里手动删除，并给出费用编号。不要用「改金额为 0」或改说明来代替删除。

## §批量导入 Excel

1. 只读用户给出的那个文件，列出 sheet 与行数，先给用户看结构。不要在目录里另找一份表格
2. 建立字段映射：sheet 列名 → 表字段。对不上的列出来交给 `当前界面技能`，不要猜
3. 校验并把每行分类：

| 类别 | 判据 | 处理 |
|---|---|---|
| 通过 | 必填齐全、金额是数字、无重复 | 待写入 |
| 缺字段 | 缺项目、金额或日期 | 列出，不进写入 |
| 退款 | 负数，且能对上同一项目下的原支出或原收入 | 按 rules §2.1 记负数并冲销。对不上原单就列出，不写入 |
| 金额异常 | 非数字，或绝对值超过 1 亿（多半是小数点或单位错了） | 列出，不进写入 |
| 疑似重复 | 同人 + 同金额 + 同日 + 同项目（rules §7） | 列出，让用户确认 |

4. 预览每个 sheet 的识别条数、可通过条数、异常条数，异常逐条给原因
5. 预览交给 `当前界面技能`。用户提交后逐条 create。失败即停，报告已写入条数和失败行号。中途失败后重试前，先按 §7 再查一遍，避开已经写上的行
6. 收尾汇总：写入多少条、跳过多少条、原因是什么

超过 50 行时先说明逐条写入要一会儿，等用户确认再开始。
