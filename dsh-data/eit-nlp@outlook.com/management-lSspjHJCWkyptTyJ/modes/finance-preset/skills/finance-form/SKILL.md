# 财务表单

`finance-funds` 决定记什么、能不能写。本技能决定用户看见什么。先加载 `finance-funds`，再按这里出界面。先追问会让用户把同一件事打两遍，所以缺的格子留在表单上。

## 什么时候用哪种界面

- 查费用、经费概览、写入后的状态回显：`render_ui`，`mode` 为 `display`。`business_data` 只放刚读到的项目名、日期、金额、合计、使用率、盈亏和风险判断。
- 记费用、改费用、新建项目、发票确认、导入预览：`render_ui`，`mode` 为 `form`，`intent` 为 `generic_pick_one`。用户提交表示确认，然后才按 `finance-funds` 写入。

`generic_pick_one` 需要 `business_data` 里有真实候选项。文本可以是空字符串。选择字段必须带上真实选项，选中项可以空着。不要因为还有空格子就改去 `ask_user_question`。

## 格子怎么填

用户原话里已经说清的值填上。没说的留空，不要猜。

选择字段用这些真实选项，不要现编：

| 字段 | 选项从哪来 | 用户没说时 |
|---|---|---|
| 项目 | `项目预算表` 里的项目。0 条命中时加上「新建：<用户说的名字>」 | 不预选 |
| 经费来源 | IDT、EIT | 不预选 |
| 项目类型 | 横向、纵向 | 不预选 |
| 费用类型 | 本轮读到的线上选项 | 不预选 |
| 是否与项目相关 | 是、否 | 不预选 |
| 付款方向 | 支出、收入、支出冲销、收入退回。能对上 rules §2.0 就预选 | 不预选 |
| 启动资金 | 预算、已到账 | 不预选 |

人员、金额、说明、项目编号、申请日期是文本。知道就填，不知道就空字符串。申请日期若是「昨天」这类说法，填换算后的具体日期。余额变化用刚读到的 `剩余金额` 现算。新的单选值要在表单上写「将新增选项：X」。

## 提交之后

必填项还空着，就再出同一张表单，标出空着的格子，不要写入，也不要改用 `ask_user_question`。费用至少要有项目、金额、付款方向、是否与项目相关。新建项目至少要有名称、项目编号、经费来源、项目类型，以及启动资金是预算还是已到账。

必填项齐了才写入。只写用户提交的值。

## 渲染失败

`render_ui` 失败时，用同一批字段打一张文字表，空格子留空，然后停下来等用户补充。不要接着调用 `ask_user_question`。
