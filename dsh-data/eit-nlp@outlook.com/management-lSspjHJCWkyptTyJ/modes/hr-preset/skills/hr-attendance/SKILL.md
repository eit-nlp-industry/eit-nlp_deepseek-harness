# 月考勤

飞书多维表格是唯一账。读写用本会话的 `mcp__feishu__*` 工具。需求里说的「飞书 CLI」就是这些工具，不要再在 shell 里找命令，也不要自己 curl。

本预设没有 `render_ui`。缺的必要信息用一次 `ask_user_question` 问完，齐了用文字卡片确认，用户明确同意后才写入。「好的」「嗯」不算同意。

人是谁、团队里有哪些人，按 `hr-employees` 查员工主档。本技能不新建员工，也不把岗位和职级写进考勤。

钉钉是导出的来源，不是这里能连上的系统。用户没交出 Excel、也没念出数字时，不要假装去钉钉查。

## 数据源

- base：`CE4Xbin7faAeUPsIepncBBGUnSf`
- `03 月考勤` `tblEq4NyertKG2XZ` — 一个人、一个月一行
- `员工` 关联到 `01 员工主档` `tbl3LF4aRXl6MqE6` 的 `record_id`

直接用这个 table id。读失败再列出数据表。本轮用字段列表工具读一次字段和单选选项，后面复用。下面的名称是口径；对不上就用含义相同的线上字段，没有就停下来说明。

## 三条硬规则

1. **确认后才写**。单条、修改、导入都先出卡片或预览。用户改哪一项，就只改那一项再确认一次。
2. **只写可写列**。`出勤率` 和 `员工编号` 是公式，不写。单行出勤率读公式。应出勤为 0 或空、或实际出勤为空时，公式是空的，回复写「不适用」，不要写成 0%。
3. **空和 0 不是一回事**。用户没说、Excel 里也没有的数字留空。不要为了填满写成 0。0 只在用户或表格明确给出 0 时写入。空的实际出勤不会产生出勤率，写成 0 就会变成 0%。

同一人、同一个月份已经有行，就改那一行，不要再新增。人还没链上主档时，用姓名加月份判断。

## 月份和人

`月份` 是文本，写成 `YYYY-MM`，例如 `2026-10`。用户只说「10 月」时用今年，卡片上写明年份。表里如果已经有「2026年10月」这种写法，查询时按同一个月份认，写入新行仍用 `YYYY-MM`。

`员工` 只放一条主档 `record_id`。`姓名` 写用来匹配的那个名字，这样不点开关联也能看见是谁。主档姓名和表格姓名不一致时，卡片里两处都写上。对不上主档时仍可按用户的决定记下姓名，关联留空，并标成「未关联主档」。不要为了导入去新建员工。

`考勤组` 当前选项是技术组 / 科研组。它和主档上的所属团队不是一回事。用户说「NLP 组」时按主档团队筛人，不要写成考勤组。用户没提考勤组就留空。

`确认状态` 当前选项是待确认 / 已确认 / 有异议。导入和补录没说确认结果时写成待确认，并在卡片上写明。已经是已确认或有异议的行，不要因为重新统计就改掉。

## 数字口径

应出勤天数、实际出勤天数、请假天数、迟到次数、早退次数、缺卡次数、加班时长，按用户或 Excel 的原数写入。加班时长不换算单位。

请假拆开的列是：事假天数、病假天数、年假天数、婚假天数、产检假天数。表格只有这些拆分、没有请假天数时，请假天数等于这五项之和，卡片上写明「请假天数由拆分相加」。调休天数和旷工天数单独放，不并进请假天数，除非用户说这份表的请假已经含在里面。

组别出勤率用实际出勤合计除以应出勤合计。只加总应出勤大于 0、且实际出勤有数的行。不要把每人的出勤率再平均，也不要把单行公式里 0 到 1 的截断用到合计上。合计应出勤是 0 时写「不适用」。

## 查和统计

先定月份，再定范围。没说人、团队或考勤组，就查这个月的全部记录，并另列主档里试用期、在职、但这个月没有行的人。

按这个结构回复。某一类没有就省略这一行：

```
<YYYY-MM> 考勤（<范围>）
有记录 / 应统计：
应出勤合计 / 实际出勤合计：
组别出勤率：
请假天数合计：
迟到 / 早退 / 缺卡 / 加班：
确认状态：待确认 n、已确认 n、有异议 n
异常：
- 缺少记录：应统计但这个月没有行的姓名
- 出勤率不适用：应出勤为 0 或空，或实际出勤为空
- 天数对不上：实际出勤大于应出勤；或实际出勤、请假天数、旷工天数都有数，三者之和与应出勤相差超过 1 天
- 迟到、早退、缺卡：次数大于 0 的人，写明哪一项和次数
- 未关联主档：
- 有异议：
```

这些异常只提示核对，不要自动改数字。

用户要看几个月的变化时，每个月一行，列月份、组别出勤率、迟到次数合计、缺卡次数合计。没有记录的月份不编 0，写「无记录」。

## 录入和修改

1. 抽出人、月份，以及用户说出的那些数字、考勤组、异议或确认。
2. 人在主档对不上或有多条，先按 `hr-employees` 让用户选定。用户坚持先记名字时，关联留空。
3. 这个月已有行就改原行，卡片写「原值 → 新值」。只改用户点到的字段。
4. 确认后写入。回读姓名、月份、`record_id`。

记录编号没给出就留空，不要自己编。

## 导入 Excel

只读用户这次交出的那个文件。先列出 sheet 和行数，再给列怎么对上字段。对不上的列单独列出来，不要猜进某个数字。

每一行归进一类：

| 类别 | 怎么认 | 怎么处理 |
|---|---|---|
| 可写入 | 有姓名、有月份或用户已指定整份文件的月份，数字是数 | 进入预览 |
| 缺人 | 没有姓名 | 不写入 |
| 未关联 | 姓名在主档没有唯一命中 | 列入预览，默认不链员工；用户确认后可以只写姓名 |
| 疑似重复 | 同一个人、同一个月份已经有行，或文件里自身重复 | 列入预览，默认改原行而不是再新增 |
| 异常 | 数字不是数，或撞上上一节的天数对不上 | 列入预览，不自动改 |

预览写明识别多少行、可写多少行、跳过多少行，异常逐条给原因。超过 50 行时先说明要逐条写入，等用户确认再开始。

当前连接没有批量工具。用户确认后逐条 create 或 update。失败就停，报告已写入条数和失败行。再继续之前，先按人和月份查一遍，避开已经写上的行。

## 确认和异议

发起确认：把这次范围内确认状态还空着的行写成待确认。已确认和有异议的不动。卡片写将要改成待确认的人数，同意后再写。

员工提出异议：找到该人该月，状态改为有异议，异议原话追加进备注。先不要改出勤数字。

HR 处理异议：卡片并列异议、现有数字、准备改成的数字和确认状态。同意后只写这些变更。

删除：当前连接没有删除工具。要删某月记录时说明需要在多维表格里手动删除，并给出 `record_id`。不要把天数改成 0 来代替删除。

## 出错时

- 找不到 `mcp__feishu__*` → 提示用户切到「人事管理」预设
- `99991672` → 说明缺哪个 scope（`base:table:read` / `base:field:read` / `base:record:create` / `base:record:update`），不要重试
- 员工关联写入失败 → 不要改成只留姓名再偷偷重试，回到预览说明这行没链上主档
