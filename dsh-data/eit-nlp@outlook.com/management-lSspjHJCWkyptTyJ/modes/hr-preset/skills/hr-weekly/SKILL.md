# 周产出

飞书多维表格是唯一数据源。读写用本会话的 `mcp__feishu__*` 工具。需求里说的「飞书 CLI」就是这些工具，不要再在 shell 里找命令，也不要自己 curl。

本预设没有 `render_ui`。缺的必要信息用一次 `ask_user_question` 问完，齐了用文字卡片确认，用户明确同意后才写入。「好的」「嗯」不算同意。

人是谁、团队里有哪些人，按 `hr-employees` 查「01 员工主档」。本技能不新建员工，也不把岗位、职级、团队抄进周产出。

## 数据源

- base：`CE4Xbin7faAeUPsIepncBBGUnSf`
- `02 周产出` `tbln37wdrvwr31sn` — 一个人、一周一行
- 员工关联到 `01 员工主档` `tbl3LF4aRXl6MqE6` 的 `record_id`

直接用这个 table id。读失败再列出数据表。本轮用字段列表工具读一次字段和单选选项，后面复用。下面的名称是口径；对不上就用含义相同的线上字段，没有就停下来说明。不要沿用旧选项，也不要现编。

## 三条硬规则

1. **确认后才写**。新增和修改都先出卡片。用户改哪一项，就只改那一项再确认一次。
2. **只写可写列**。当前这些是公式或查找，一律不写：`完成率`、`完成率%`、`查重键`、`重复计数`、`员工编号`、`员工账号`。单人的完成率读公式；公式为空但计划数和已验收数都有时，再按下面的口径算，并注明「本次为手工计算」。
3. **不猜验收**。做完不等于验收通过。用户或文档没明确说验收通过，就不要改 `已验收数`。状态、对应考核项、目标完成日期，没说就留空。单选和多选只用本轮读到的选项。

## 一周指哪一天

`week_start` 是这一周的周一。用户说「本周」「上周」「某月某日那周」时，先换成那个周一的日期，卡片上写成 `YYYY-MM-DD（本周或上周）`。写入用当天 00:00 的毫秒时间戳。同一人、同一个周一已经有行，就改那一行，不要再新增。`查重键` 是员工编号加这一天，用来发现重复；人还没有员工编号时，仍按「员工 record_id + 周一日期」自己判断。

`员工` 只放一条主档 `record_id`，值是 record id 数组。一个团队的周产出是多行，不是把整组人链到同一行。

## 字段怎么写

| 用户在说的事 | 写入 |
|---|---|
| 具体任务、计划或关键成果 | `关键产出摘要` |
| 计划交付多少项 | `计划交付数` |
| 已经验收通过多少项 | `已验收数` |
| 希望哪天交付 | `目标完成日期` |
| 这次内容从哪来 | `来源`：对话写「对话」，从文件来写文件名 |
| 验收说明、对不齐的地方 | `备注` |

`来源` 只说明出处，方便以后对上那次提交。用户没另指定时用「对话」或文件名，这不是在猜业务内容。

验收状态的当前口径：已验收 / 部分交付 / 待验收 / 未完成 / 未统计。

- 明确验收通过 → 已验收
- 计划里的事做完了，但没说验收 → 待验收
- 只做完一部分 → 部分交付
- 明确没做完 → 未完成
- 记录在，但还没人整理 → 未统计

对不上这些词就留空，并在卡片上写「将新增选项：X」。对应考核项是多选，只有用户把工作对上考核项时才写。当前口径是「1 代码/模型资产与文档质量」到「9 责任心、预警与跟进」这九项，以本轮选项为准。

## 查

先定人、团队和周一。团队按主档的 `所属团队` 找成员；用户说「部门」时也用这个字段。相近写法（「NLP组」和「NLP 组」）列出来问，不要合并。统计范围默认是这些成员里状态为试用期或在职的人。用户点名要看离职或待入职的人再加。

一个人一周：列出关键产出摘要、计划交付数、已验收数、完成率、验收状态、目标完成日期、备注。空的不写。

一个团队一周，按这个结构回复，数字只用刚读到的值。某一类是 0 或没有人时，那一行省略：

```
<范围>（<周一日期> 当周）
计划交付总数：各行计划交付数之和
已验收总数：各行已验收数之和
整体完成率：已验收总数 / 计划交付总数
人均产出：已验收总数 / 统计人数
统计人数 / 已提交：应统计的人 / 这一周有记录的人
验收状态：按状态数有记录的行
未提交：这一周没有记录的姓名
待验收：状态为待验收的姓名
未统计：状态为未统计，或状态空着的姓名
```

整体完成率用两边的合计相除，不要把每个人的完成率再平均。计划交付总数是 0 时写「无法计算」。统计人数是 0 时，人均产出也写「无法计算」。

## 提交计划

1. 从原话抽出人、周一、任务、计划交付数、目标完成日期。
2. 人在主档里对不上，或同一姓名有多条，先按 `hr-employees` 让用户选定。没有主档就不写周产出。
3. 人和周一都有了，再查这一周是不是已经有行。有就改走更新，卡片写「原值 → 新值」。
4. 计划交付数和关键产出摘要至少要有一项。两项都缺就问一次。
5. 确认后写入。回读 `record_id`、姓名、周一和写上的字段。

## 从周进度文档整理实际交付

只读用户这条消息里交出的那一个文件，或用户给出的那一个路径。不要在目录里再找一份周报。

1. 抽出实际做完的事项、数量和关键成果，并对照该人该周已有的计划。
2. 没有计划行时，卡片里说明「这周还没有计划」，问是给这周新建，还是只先把实际内容记上。仍然先确认再写。
3. 卡片分两列意思：原来的计划摘要，文档里的实际交付。更新后的摘要要保留计划里还没被实际覆盖的任务，不要只剩实际、把计划抹掉。
4. 文档没写验收通过：状态按上一节放到待验收、部分交付或未完成，`已验收数` 保持原值。
5. 文档写明验收通过：状态改为已验收，`已验收数` 用文档里说清的数量。数量对不上计划交付数时，差额写进备注，不要偷偷改计划数。

## 验收

待验收清单：筛 `验收状态` 为待验收的行；用户要看还没结案的，把部分交付一并列入。可以再按人、团队、周一收窄。每行给姓名、周一、计划交付数、已验收数、摘要。

更新验收时只改用户指定的行。卡片写验收状态、已验收数、备注的「原值 → 新值」。通过多少项没说清就问一次，不要用计划交付数代替已验收数。

## 查缺提醒

异常就是上一节统计里的未提交、未统计、待验收，再加上 `重复计数` 大于 1 的行。先把名单回复给当前用户。

周产出查缺只把名单回复给当前用户，不调用发消息。用户明确要求发到员工飞书时，改加载 `hr-notify`。用户要以后再自动查一次时，用 `schedule_create` 把同一段统计指令投到本会话，到点再按本技能查并回复。

删除：当前连接没有删除工具。要删一周记录时说明需要在多维表格里手动删除，并给出 `record_id`。不要把计划交付数改成 0 来代替删除。

## 出错时

- 找不到 `mcp__feishu__*` → 提示用户切到「人事管理」预设
- `99991672` → 说明缺哪个 scope（`base:table:read` / `base:field:read` / `base:record:create` / `base:record:update`），不要重试
- 员工关联写入失败 → 不要改成写姓名再试，回到卡片说明这条没链上主档
