# 飞书通知

发消息用本会话的 `mcp__feishu__im_v1_message_create`。这是应用身份的单聊，不是用户自己的飞书账号。收件人是谁按 `hr-employees` 查员工主档。本技能不改表。

本预设没有 `render_ui`。缺的必要信息用一次 `ask_user_question` 问完。「好的」「嗯」不算同意。

## 收件人

`data.receive_id` 只用该员工主档「员工账号」里的用户 id。`params.receive_id_type` 固定 `open_id`。

员工账号为空：这个人放进「未能发送」，写明缺飞书用户。不要用姓名、邮箱或手机号代替，不要改发到群里。

同一个人评多个人或收多条内容时，合成一条消息。同一轮里同一个 id 只调用一次。

## 正文

`data.msg_type` 固定 `text`。`data.content` 是 JSON 字符串，形如 `{"text":"正文"}`。

正文只用用户确认过的事实：谁、哪件事、截止时间。用户没要求带分数、评语或他人材料时，不要写进去。

`data.uuid` 每次成功发送用一个新值。一小时内不要把同一个 uuid 用到另一段正文上。

## 当场发送

1. 列出收件人姓名、是否已有员工账号、完整正文。
2. 用户明确同意后才逐个发送。
3. 某条失败就停。回复已发送的姓名和失败原因。工具没返回成功，就不要说已经通知了。
4. 返回码 `99991672`：说明应用还不能发消息，把剩余的人列为未发送，不要改参数重试。

## 到点再发

用户要以后自动发时，先问清两点：每个工作日几点，发到哪一天。用 `schedule_create`，`target` 用 `new_once`。

`prompt` 写清这四项：季度或事项、怎样判断仍要发送、确认过的正文模板、以及用户同意到点直接发送的原话。指令里要求重新查当前数据，只发给仍未完成的人，并按本技能调用发消息。

用户只是要到点在会话里看到名单、没有同意代发：`prompt` 写明只回复名单，不要调用发消息。`target` 仍用 `new_once`。

同一事项已有定时任务就改时间，不另建一条。名单已经没有待发送的人时，关掉这个任务，并在会话里说明已停止。
